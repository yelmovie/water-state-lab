# 0. 이번 심화 설계의 핵심

기존 「물방울 연구실」의 장점인

- 물의 상태를 직접 조작하는 인터랙션
- 얼기 전후의 측정과 예상 비교
- 증발·끓음의 동시 관찰
- 응결의 증거 기반 추론
- 3D 물 수집 장치 설계
- 태블릿 고유 상호작용
- 5 Stage / 10 Screen 구조

는 유지한다.

이번 수정에서는 이를 Science World 공통 메타 구조인

**QUEST → EVIDENCE → WORLD CHANGE → FINAL REPORT → FINAL ACTION → FINAL MOVIE → CERTIFICATE**

로 연결한다.

학생 경험의 최종 목표는

> “물의 상태 변화 문제를 풀었다.”

가 아니라

> **“내가 직접 관찰하고 측정하고 실험해서 연구실의 물 순환 시스템을 복구했다.”**

가 되도록 한다.

# 1. 교육과정 기준

## [4과10-01]

물이 세 가지 상태로 변할 수 있음을 알고, 우리 주변에서 예를 찾을 수 있다.

### 게임 설계 연결

단순히 고체·액체·기체 버튼을 맞히는 활동으로 끝내지 않는다.

학생이 직접

- 물을 다른 용기에 붓기
- 얼음을 잡고 회전하기
- 젖은 표면의 시간 변화를 관찰하기
- 차가운 물체 표면을 닦고 다시 관찰하기
- 관찰 근거를 기록하기

과정을 거친 뒤 상태를 판단한다.

---

## [4과10-02]

물이 얼 때, 얼음이 녹을 때, 물이 증발할 때와 끓을 때, 수증기가 응결할 때의 변화를 관찰할 수 있다.

### 게임 설계 연결

학생이

**예상 → 조작 → 변화 관찰 → 측정 → 비교 → 증거 판단 → 재실험**

을 수행하도록 한다.

특히 다음을 구현한다.

- 얼기 전후 수위 비교
- 얼기 전후 무게 비교
- 증발과 끓음의 변화 위치 비교
- 시간에 따른 물의 양 변화
- 차가운 표면의 물방울 생성
- 응결 전후의 무게 변화
- 생활 속 상태 변화 사례 적용

---

## [4과10-03]

물의 상태 변화를 이용하여 물을 얻을 수 있는 장치를 설계하고 만들 수 있다.

### 게임 설계 연결

정답 모양 하나를 따라 만드는 방식이 아니라

**설계 → 시험 가동 → 물방울 경로 확인 → 손실 지점 발견 → 수정 → 재시험**

구조로 구현한다.

# 2. 과학적 정확성 절대 규칙

## 2-1. 입자 수준 설명 금지

4학년 학습 범위에서는 물의 상태 변화 원인을 분자·입자 운동 수준으로 설명하지 않는다.

따라서 다음과 같은 화면은 사용하지 않는다.

- 물 분자가 빨리 움직이는 애니메이션
- 수증기 입자가 공중을 날아다니는 캐릭터 연출
- 분자 배열 변화로 상태 변화를 설명하는 화면

---

## 2-2. 수증기는 눈에 보이지 않는다

화면에 보이는 흰 김·안개·구름을 그대로 ‘수증기’라고 표현하지 않는다.

### 제작 규칙

- `수증기 = 기체 상태의 물, 눈에 보이지 않음`
- 하얗게 보이는 김 = 작은 물방울이 섞여 보이는 현상으로 별도 처리
- 캐릭터 디자인에서도 ‘구름 캐릭터 = 수증기’라는 오개념을 만들지 않는다.

기존 샘플 화면에 사용된 구름형 ‘수증이’는 **최종 캐릭터로 확정하지 않는다.**

---

## 2-3. 3D 가상 실험의 수치는 교육용 비교값

3D 배관 실험과 물 수집 장치의 수치는 실제 공학·유체역학 계산값처럼 표현하지 않는다.

예:

- `배관 압력 132%`처럼 실제 측정값처럼 보이는 표현은 지양
- `위험 낮음 / 보통 / 높음`
- `가상 시험 수집량`
- `가상 시험 효율`

처럼 교육용 시뮬레이션임을 명확히 한다.

---

# 3. 첨부 자료 벤치마킹 원칙

첨부 PPT·PDF·활동지는 **기능과 학습효과를 높이기 위한 참고자료**로만 사용한다.

## 참고하는 것

### 얼음 속 인형 구출 활동

**문제 상황 → 해결 방법 선택 → 실제 변화 관찰**

이라는 구조를 참고한다.

### 물·얼음 관찰 활동

물과 얼음의

- 모양
- 잡을 수 있는지
- 상태
- 시간에 따른 변화

를 직접 비교하는 탐구 요소를 참고한다.

### 사라지는 물그림

학생이 직접 만든 물 흔적이 시간에 따라 변하는 경험을 참고한다.

디지털에서는

- 자유 그리기
- 물 양 변경
- 붓 굵기 변경
- 시간 스크럽
- 조건 비교

기능으로 확장한다.

### 증발·끓음 비교 학습

두 현상의 공통점과 차이점을 비교하는 교육 요소만 참고한다.

빈칸 표를 화면에 그대로 옮기지 않는다.

### 응결 실험

- 표면 닦기
- 입구 밀봉
- 처음 무게 측정
- 시간 변화 관찰
- 나중 무게 측정
- 물방울 출처 추론

이라는 증거 기반 탐구 구조를 적극 활용한다.

### 생활 속 적용 사례

- 차가운 음료 용기
- 수도관
- 얼음틀
- 아침 이슬
- 냄비 뚜껑 안쪽

등의 생활 맥락을 활용한다.

## 사용하지 않는 것

- 기존 PPT 레이아웃 그대로 복제

- 점수 + 별 + 폭죽으로 끝나는 구조

# 4. 기존 설계 진단

# 4-2. 개선할 부분

## 샘플 화면의 ‘별/진행도’는 보조 정보로 축소

샘플 이미지에서 별 아이콘과 `1/10` 진행 표시가 눈에 잘 띄지만 실제 구현에서는 학습 행동보다 앞에 나오지 않게 한다.

### 최종 구현

- 작은 진행도
- Evidence 1/5
- 연구 복구율
- Mission 상태

중심으로 변경한다.

---

## Stage 2 배관 화면의 ‘안전 범위 정답 찾기’ 느낌 제거

단순히 슬라이더를 특정 위치에 맞추면 성공하는 구조가 되면 유치해질 수 있다.

### 수정

학생이 최소 2~3개의 서로 다른 물 양을 직접 시험하고

**얼음이 차지한 공간을 비교한 뒤 근거를 제시**

해야 완료된다.

---

## Stage 3 비교 화면에서 정답을 먼저 보여주지 않는다

샘플 이미지의 공통점/차이점 영역은 최종 결과 시각화로는 좋다.

하지만 처음부터 정답 카드가 보이면 학습지가 된다.

### 수정

학생이 놓은

- 관찰 핀
- 수위 기록
- 기포 관찰
- 시간 기록

을 바탕으로 공통점/차이점 패널이 **점진적으로 생성**된다.

---

## Stage 4 응결 화면의 객관식 원인 선택 제거

샘플 화면 하단의

- 공기 중 수증기 응결
- 컵에서 물이 샘
- 저울 고장

같은 선택지는 보조 진단용으로만 사용 가능하다.

핵심은 다음 페이지의 Evidence Board에서 학생이 직접 얻은 증거를 연결하는 것이다.

---

## Stage 5 수집 장치의 수치 표현 개선

`120개 / 78개 / 42개 / 65%`처럼 보이는 수치는 이해는 쉽지만 실제 과학량처럼 오해될 수 있다.

### 최종 표현

**가상 시험 결과**

- 생성된 물방울 지수
- 수집 지수
- 손실 지수
- 수집 효율

또는 상대 단위로 표현한다.

# 6. 단원 메인 퀘스트

# WORLD INCIDENT

## 사건

물방울 연구실의 중앙 **Water Core**가 멈췄다.

Water Core는 연구실의

- 얼음 냉각 구역
- 물 실험 수로
- 증발 관찰 구역
- 응결 수집 구역
- 최종 물 수집 장치

를 연결하는 핵심 시스템이다.

그런데 상태 변화 연구 데이터 5개가 분리되면서 연구실의 물길이 끊겼다.

### 현재 상태

- 상태 판별 데이터 누락
- 냉각 배관 이상
- 증발·끓음 관찰 장치 정지
- 응결 수집 구역 데이터 불명
- 최종 물 수집 장치 미완성

---

# QUEST RECEIVE

방울이가 학생에게 메인 퀘스트를 의뢰한다.

> “Water Core를 다시 움직이려면 다섯 연구 기록이 필요해.  
> 네가 직접 실험해서 기록을 다시 만들어 줄래?”

학생의 역할:

**물방울 연구실 신입 연구원**

---

# 최종 목표

5개의 Mission을 수행하여 Evidence를 확보한 뒤

Water Core에 연구 데이터를 적용하고,

학생이 직접 설계한 물 수집 장치를 마지막으로 가동하여

**연구실 전체의 물길을 복구한다.**

# 8. Mission 1~5 심화 설계

## MISSION 01 — 같은 물, 다른 모습

### 유형

OBSERVE

### 학습목표

물의 세 가지 상태와 생활 속 사례를 관찰 가능한 특징을 근거로 판단한다.

### 퀘스트 상황

Water Core가 현재 물질의 상태를 구분하지 못해 수로 제어가 멈췄다.

### 학생 핵심 행동

- 물 붓기
- 얼음 잡기/회전
- 젖은 표면 관찰
- 차가운 캔 표면 닦기
- 확대/스캔
- 상태 판단
- 증거 선택

### Micro Loop

```text
대상 선택
→ 직접 조작
→ 물체 반응
→ 특징 관찰
→ 상태 예상
→ 증거 선택
→ 부족하면 다시 관찰
→ 기록 완료
```

### 실패/재시도

상태만 맞고 근거가 부족하면

라고 안내한다.

### 과학적 피드백

- 얼음 모양은 유지
- 젖은 자국이 시간에 따라 변화
- 닦은 캔에 물방울이 다시 생김

현상으로 보여준다.

### Evidence

**상태 관찰 기록**

### World Change

상태 판별실의 3개 상태 표시등이 복구되고 첫 번째 파이프에 물이 흐른다.

## MISSION 02 — 얼음 배관의 이상

### 유형

INVESTIGATE

### 학습목표

물이 얼 때와 얼음이 녹을 때의 변화를 관찰하고 얼기 전후의 부피와 무게를 비교한다.

### 퀘스트 상황

냉각 배관이 특정 조건에서 손상되고 있다.

원인을 알려면 먼저 얼기 전후의 변화를 측정해야 한다.

### 학생 핵심 행동

- 초기 수위 표시
- 전자저울 영점 확인
- 초기값 기록
- 얼었을 때 수위 예상
- 냉각 레버
- 결과 측정
- 예상과 실제 겹쳐 보기
- 3D 배관 여러 조건 시험

### Micro Loop

```text
예상
→ 측정 준비
→ 냉각
→ 얼음 생성
→ 결과 비교
→ 배관 조건 설정
→ 시험
→ 공간 확인
→ 조건 수정
→ 재시험
```

### 실패/재시도

위험한 조건에서 배관에 이상이 나타나면

> “틀렸어.”

라고 하지 않는다.

배관 내부의 얼음과 남은 공간을 확대 표시하고

> “처음 조건과 무엇이 달랐을까?”

라고 묻는다.

### Evidence

**얼기 전후 측정 데이터**

- 초기 수위
- 예상 수위
- 실제 수위
- 초기 무게
- 결과 무게
- 배관 조건 비교 기록

### World Change

냉각 구역 파이프가 다시 연결되고 얼음 저장 탱크가 가동된다.

- 나중 무게 측정
- Evidence 캡처
- 원인 → 조건 → 결과 연결
- 생활 사례 적용

### Micro Loop


라고 질문한다.

### Evidence

**응결 증거 보고서**

### World Change

### 퀘스트 상황

- 재시험
