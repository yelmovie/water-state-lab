# 물방울 연구실 · 물길 탐험 3.0

물의 상태 변화를 관찰·측정·비교·설계해 멈춘 연구실을 복구하는 4학년 과학 웹게임.

## 공개 주소와 배포

- 게임: https://water-state-lab.pages.dev/
- 저장소: https://github.com/yelmovie/water-state-lab
- 콘텐츠명: 방울이의 물길 탐험

초등 4학년 과학 「물의 상태 변화」를 바탕으로 한 퀘스트형 디지털 탐구 게임입니다. 방울이와 물을 붓고 얼리고 녹이며 증발과 응결을 관찰·비교합니다. 10개의 실험·현장 의뢰에서 모은 증거로 물 수집 장치를 설계하고, 멈춘 연구섬의 물길을 복구합니다.

Cloudflare Pages에 빌드 결과를 직접 업로드한다. Wrangler 4와 Cloudflare 인증을 준비한 뒤 실행한다.

```powershell
npm run build
wrangler pages deploy dist --project-name water-state-lab --branch main
```

배포 설정은 `wrangler.jsonc`에 보관한다. GitHub 푸시와 운영 배포는 각각 실행하며, 자동 배포 연동은 설정하지 않는다.

## 실행

Node.js 20 이상에서 설치 없이 실행:

```powershell
npm start
```

브라우저에서 `http://127.0.0.1:4316`을 연다. 포트 변경은 `$env:PORT='다른번호'` 후 실행한다. 실행 중 터미널을 종료하면 서버도 종료된다.

```powershell
npm run check
npm test
npm run build
npm run preview
```

`npm run preview`는 빌드된 사이트를 `http://127.0.0.1:4317`에서 실행한다. `dist/`는 별도 런타임 의존성 없는 정적 사이트다. 도메인 루트에 서비스한다. HTML 파일을 더블클릭하는 file:// 실행은 ES 모듈 제한 때문에 지원하지 않는다. GitHub Pages 하위 경로 배포는 경로 변경이 필요하다.

## 구성

- 첫 화면부터 생성 이미지로 구성한 연구섬 지도. 길과 구역 위로 방울이가 이동하고, 완료한 구역의 물길이 표시된다.
- 1~10장: Phaser Canvas로 직접 도구를 움직이는 2D 실험. 버튼·SVG·DOM 대체 조작과 기록 화면 제공.
- 5개 연구 기록, 단계 해금, 연구노트, 코어 직접 연결·밸브·레버, 결과와 인쇄 인증서.
- 자동 저장, 움직임 줄이기, 마우스·터치·키보드 대체 조작.
- 각 현장 의뢰를 해결한 뒤 9초 개념 영상 10편, 두 단계 방울이 힌트, 물체·목적지를 차례로 누르는 대체 조작.

2026-10-22 개편: [영상 제작 명세](docs/design/CONCEPT-CLIPS-2026-10-22.md), [화면·미디어 검증](docs/reviews/EXPERIENCE-2026-10-22.md). 효과음은 Kenney Interface Sounds(CC0 1.0)이며 출처·라이선스를 `public/assets/audio/`에 보관한다. 영상·효과음 모두 빌드에 포함되어 외부 음원 사이트 요청 없이 재생된다.

추가 브라우저 검증은 서버를 실행한 뒤 `QA_URL`을 지정하고 `npm run check:experience`로 수행한다. Python Playwright와 Chrome이 개발 환경에 필요하다.

자세한 시나리오와 범위는 `water-drop-lab_PRD.md`, 기술 구조는 `water-drop-lab_TRD.md`, 점검 결과는 `docs/MVP-VALIDATION.md`를 참고한다.

## 수업에서

학생은 지도에서 순서대로 미션에 들어간다. 관찰·측정 기록을 확보해야 다음 장으로 이동한다. 장치 공방은 실패한 곳을 수정한 뒤 재시험해야 완료할 수 있다. 드래그 대신 선택 메뉴와 방향 버튼으로 부품을 옮길 수 있다. 대부분의 실험은 물체를 선택한 뒤 목적지를 누르거나 ‘버튼으로 조작하기’를 열어 수행할 수도 있다.

관찰 전 예상의 정오를 채점하지 않는다. 배관 시험은 물이 얼며 차지하는 공간을 비교하는 단순 모형이며 실제 수도관의 안전 수칙·공학 계산이 아니다. 장치 지수도 실제 수집량이 아닌 가상 비교 지수다.

## 저장과 개인정보

브라우저 localStorage의 `water-drop-lab:v1`에 실험 상태만 저장한다. 인증서 별명은 메모리/인쇄 화면에서만 사용하고 저장하거나 전송하지 않는다. 외부 API, 분석 SDK, CDN, 로그인은 없다. 저장소 접근 차단 시 메모리로 실행하지만 새로고침 후 이어하기는 불가능하다. 호스트/포트가 다르면 별개 진행으로 저장되므로 로컬·미리보기·배포 주소 사이에 기록이 공유되지 않는다.

## 현재 범위와 제한

도입과 엔딩은 일러스트·게임 내 연출이며 영상·음성은 없다. 스테이지 해결 후 개념 영상 10편을 제공한다. 배경 음악은 자체 Web Audio 합성이며 효과음은 로컬 Kenney CC0 음원을 사용하고 재생 실패 시 합성음으로 대체한다. 설정에서 따로 켜고 끌 수 있고 배경 음악만 음량을 조절한다. 교사용 전체 해금은 학생 기록과 분리된 시연이다. 터치 실기기, 학교 네트워크, 전자칠판 뒷자리 가독성은 별도 확인이 필요하다. 외부 공개 배포는 수행하지 않았다. 자동 오프라인 캐시는 없으므로 접속·새로고침·아직 받지 않은 이미지에는 네트워크가 필요하다.

## 2026-10-15 활동 개편

- 1~2: 두 그릇에 붓기, 얼음 이동, 천 문지르기·시간 관찰, 실험/생활 장면 분류.
- 3~4: 예상선을 남기고 같은 물의 얼기·녹기 기록 비교, 서로 다른 두 배관 채움 조건 시험.
- 5~6: 직접 그린 물그림의 세 시점 기록, 무가열 대조 조건과 끓는 조건 비교, 돋보기 관찰.
- 7~8: 밀봉한 차가운/실온 용기 비교, 재닦기와 재응결, 자기 증거로 설명 구성, 음료병에 적용.
- 9~10: 이미지 부품 조립, 실패 지점 진단과 설계 수정, 저장 설계·실제 연구 기록으로 코어 가동.

`tmp/baseline-v1-src`에 개편 전 소스를 보관했다. 기존 `experiments.js`와 `map.js`는 호환 참고용으로 남아 있지만 현재 앱에서 불러오지 않는다. 추가 장면은 `activities.js`의 view/handler/bind/progress와 `activity-model.js`의 상태·완료 조건을 함께 수정하고, 전체 순서 테스트를 갱신한다.

개편 계획: `docs/reviews/UPGRADE-PLAN-2026-10-15.md`. 검증 결과: `docs/reviews/UPGRADE-VALIDATION-2026-10-15.md`.

원본 PNG는 재작업용으로 보존하고 실제 화면은 WebP를 사용한다. 과학적 변화와 물높이 등은 SVG/Canvas로 표시하며 실제 3D 엔진은 사용하지 않는다. 개발/검증/배포의 주소(origin)가 다르면 저장 기록도 서로 분리된다. 이번 브라우저 전체 순서 검증은 4318 포트를 사용했으며 사용자 4316 포트의 기록은 초기화하지 않았다.

## 2026-10-18 태블릿 실험 무대

연구섬 길 걷기, 주전자 붓기, 얼음·분류 카드·돋보기 이동, 손그림, 컵 부분 닦기, 공방 부품 이동을 Phaser Canvas에 연결했다. Phaser는 저장소의 로컬 파일을 사용하며 CDN 요청이 없다. 기록 보기·설계 비교와 버튼 대체 조작은 HTML/SVG로 유지한다.

중단된 작업을 이어 확인하면서 실험 영역이 좁아지던 그리드 충돌, 캔버스 초기 크기 계산, 작은 세로 화면의 가로 넘침을 수정했다. 검증 기록은 `docs/reviews/TABLET-VALIDATION-2026-10-18.md`에 남긴다.

아래 검사는 2026-10-18 구현 당시의 회귀 스크립트다. 3.0의 현장 의뢰 완료 관문은 아래 최신 검사로 확인한다. 브라우저 검사는 Python Playwright와 로컬 Chrome이 있는 개발 환경에서 실행한다. 앱 자체에는 Python이나 패키지 설치가 필요 없다.

```powershell
$env:PORT='4320'; npm start
# 별도 터미널
python scripts/tablet-smoke.py
python scripts/tablet-interactions.py
```

검사 전용 임시 브라우저를 사용하므로 기존 브라우저의 진행 기록을 변경하지 않는다. 다른 테스트 주소는 `QA_URL` 환경변수로 지정한다. 화면 캡처·검사 JSON은 `docs/reviews/screenshots/tablet-v3/`에 생성되며 Git 커밋에서 제외한다. 원본 제공 자료·중복 사본·임시 브라우저 프로필도 제외하며 실행 에셋과 재작업용 `public/assets/v2` 원본은 보존한다.

## 2026-10-21 · 물길 탐험 3.0

각 장은 **실험 → 관찰·비교 기록 → 현장 의뢰 → 도장·다음 구역**으로 이어진다. 기존 10개 실험에 현장 의뢰 10개를 붙였다. 첫 그림에서 방울이가 복구할 물길과 마지막 보상을 예고하고, 실험 무대에서도 도구 가까이 이동하며 도움을 준다. 시간 제한이나 반복 클릭 점수는 없다. 실제 학생의 소요 시간과 학습효과는 아직 측정하지 않았다.

- 그릇으로 옮기기, 변신길 연결, 측정 사진 배열, 통의 여유 공간 비교, 같은 물자국 펼치기, 돋보기 이동, 냉각팩 교환, 이슬받이 조립, 아래로 물길 연결, 마지막 증발·응결 회로.
- 관찰한 조건이 바뀌면 다시 시험해야 한다. 실패는 이유를 알려 주고 같은 자리에서 고칠 수 있다. 기본 실험과 현장 의뢰 모두 해결해야 다음 보상으로 진행한다.
- 탐구 여권 10칸과 도구·기록 5개, 실제 9장 설계를 읽는 10장 수리, 능력 문장을 고르는 인증서. 별명은 저장·전송하지 않는다.
- 새 도입·복구 보상 그림 2장, 같은 출처의 방울이, 로컬 Jua 글꼴, 지도·실험·설정의 색과 버튼 규칙을 적용했다.
- 설정은 배경 음악/효과음, 음악 음량, 도입 다시 보기, 잠긴 엔딩·인증서, 앱 정보, 학생·교사 안내, 출처, 확인 후 초기화 순서다. 초기화해도 오디오 설정은 유지한다.

최신 설계는 `docs/design/EXPEDITION-DESIGN-2026-10-21.md`, 점검과 남은 제한은 `docs/reviews/FINAL-CHECK-20261021.md`, 그림 제작 기록은 `docs/reviews/ASSET-GENERATION-2026-10-21.md`를 참고한다.

| 새 파일 | 역할 |

| src/fieldwork-model.js | 장별 질문·보상, 순수 활동 모형·관찰 완료 판정·저장 검증 |
| src/fieldwork.js | 현장 의뢰 Canvas, 포인터·버튼 대체 조작, 도장과 여권 |

현재 검사 결과는 52개 단위 테스트, 지도·실험·의뢰 147개 화면과 설정 7개, 16개 흐름 통과다. 일부 흐름은 유효한 선행 기록을 넣고 해당 기능부터 검증한다. 학생이 처음부터 끝까지 연속으로 수행한 관찰 연구가 아니다. 출력은 기본 `docs/reviews/screenshots/v3/`이며 `QA_OUT`으로 프로젝트 안의 다른 결과 폴더를 지정할 수 있다.

활동 수정 시에는 `fieldMissions`의 목표·보상, `fieldAction/fieldReady`의 관찰 조건, `fieldwork.js`의 장면·대체 조작을 함께 바꾼다. 기본 실험 완료 액션은 `app.js`의 `finishActions`에서 의뢰에 연결한다. 기존 스테이지 안에서 문구만 바꿀 때도 기본 실험의 비교 조건과 현장 의뢰의 비교 조건을 섞지 않는다. 새 스테이지 추가는 데이터만으로 끝나지 않으며 지도·경로·저장 검증·검사를 함께 수정해야 한다.
