# 물방울 연구실 태블릿 탐구 경험 설계

2026년 10월 16일 · 후속 구현 기준안

학생이 직접 조작한 결과를 관찰하고, 자신의 기록을 비교해 실험과 장치를 고치는 경험을 10개 장면에 연결한다. 대표 경험은 **닦은 자리에 다시 생기는 물방울**, **내 그림의 변화를 되돌려 보는 기록**, **새는 물길을 고쳐 실제로 더 모으는 장치**다.

이 문서는 구현 설계다. 함께 제공하는 `tablet-experience-preview.html`은 화면 구성과 상태 전환을 검토하는 예시이며, 운영 앱과 저장 데이터를 변경하지 않는다. 수집 지수와 화면 속 기록은 예시다.

## 1. 설계 방향과 적용 범위

### 학습 경험의 원칙

- 학생의 조작은 모양·조건·관찰 위치·결과 중 하나를 실제로 바꾼다.
- 안내는 할 일을 알려주되 관찰 전에 결과와 해결책을 말하지 않는다.
- 예상은 정오로 채점하지 않는다. 예상과 관찰을 비교한 행동에 의미를 둔다.
- 실험 기록은 숫자와 문장뿐 아니라 당시 모습과 조건을 함께 보존한다.
- 수정 전후를 같은 시간과 시작 조건으로 비교한다. 조건을 바꾼 과거 실험을 덮어쓰지 않는다.
- 필수 활동은 관찰·비교·설명으로 완결한다. 반복 클릭, 특정 숫자 맞추기, 시험 횟수만으로 완료하지 않는다.
- 태블릿의 강점은 물체와 기록을 손으로 직접 다루는 데 둔다. 동일한 학습을 마우스·키보드로도 수행할 수 있다.

### 유지할 구조

기존 JavaScript ES 모듈, DOM/SVG/Canvas 2D, 정적 실행, 5개 구역과 10개 장면, 지도 복구, 저장·이어하기, 음소거, 움직임 줄이기, 관리자 미리보기, 인증서를 유지한다. 기존 생성 배경과 캐릭터는 재사용한다.

로그인·서버·카메라·마이크·기기 기울기 권한은 추가하지 않는다. 새 프레임워크와 실제 유체 시뮬레이션도 요구하지 않는다. 장면 연출은 학습 모형과 분리한다.

### 기존 문서와의 관계

이번 경험 개편의 기능·화면·완료 조건은 이 문서를 따른다. 기존 PRD/TRD는 변경 이력을 위해 보존한다. 현재 구현의 1~8장은 `activities.js`/`activity-model.js`, 지도는 `journey.js`다. 기존 TRD에 남아 있는 `experiments.js`/`map.js`는 새 구현의 진입점으로 사용하지 않는다.

## 2. 공통 화면 설계

### 태블릿 가로 기본 배치

| 영역 | 1280×800 기준 설계 | 역할 |
| --- | --- | --- |
| 공통 헤더 | 높이 56px | 연구섬, 장면 이름, 연구노트, 소리, 설정 |
| 질문과 진행 | 높이 64px 내외 | 질문 한 줄과 현재 활동 단계 |
| 중심 작업 영역 | 남은 높이에 맞춰 확장 | 실험 무대 72%, 도구·관찰 패널 28% |
| 하단 조작 띠 | 높이 80~104px | 실험/기록 모드, 재생·멈춤, 시간, 기록 |
| 방울이 | 무대 바깥 작은 초상 56~64px | 도움이 필요할 때 한 문장, 요청하면 힌트 |

1024×768에서는 헤더와 질문을 줄여 작업 영역을 우선 확보한다. 도구 패널은 240px 안팎으로 제한하고 무대의 남은 폭을 보장한다. 핵심 조작과 그 결과는 동일 화면에서 볼 수 있어야 한다. 긴 연구노트와 상세 설명은 별도 패널 안에서 스크롤한다. 1280×720도 동일 기준으로 검증한다.

좁은 세로 화면에서는 도구 패널을 무대 아래로 옮기고 순차 조작을 허용한다. 전체 화면을 단순 축소해 글자와 손잡이를 작게 만들지 않는다. 실제 화면 높이와 safe-area를 반영하고 키보드·회전 시 조작 띠가 실험을 가리지 않게 한다.

### 시각 언어

- 기존의 크림·청록·아쿠아와 절제된 금색을 유지한다. 작업대는 불투명한 밝은 바탕으로 배경과 분리한다.
- 배경 채도와 대비를 낮추고 실험 물체, 흐르는 물, 실제 변화 지점을 가장 선명하게 표시한다.
- 제목 28~32px, 주요 안내와 버튼 18~20px, 보조 정보 14~16px. 전자칠판에서는 핵심 질문과 관찰을 확대하는 집중 보기를 제공한다.
- 중요한 버튼과 손잡이는 최소 48×48px의 터치 영역을 확보한다. 조립 부품은 그림보다 넓은 투명 판정 영역을 사용한다.
- 청록은 조작 가능/선택, 아쿠아는 물의 변화, 금색은 비교·발견, 주황은 확인할 손실 지점을 뜻한다. 색과 함께 형태·라벨을 사용한다.
- 드래그 가능한 물체에는 손잡이와 짧은 첫 조작 안내를 제공한다. 놓을 수 있는 위치는 드래그 시작 후 강조한다.
- 관찰 결과는 물체 옆에 나타난다. 중앙 팝업은 구역 완료에만 사용하며 실험 도중 흐름을 끊지 않는다.
- 버튼 대체 조작은 항상 접근 가능하게 유지한다. 터치의 운동 능력을 학습 점수로 평가하지 않는다.

### 안내 단계

1. 기본 질문: “물방울이 어디에서 멈췄을까?”
2. 관찰 힌트: “경사판 끝과 깔때기 입구를 비교해 봐.”
3. 조작 힌트: “깔때기를 조금 옮기고 다시 시험해 볼까?”
4. 시범: 해당 조작을 짧게 보여주고 학생이 직접 재시험하게 한다.

실패만으로 즉시 정답을 노출하지 않는다. 도움 요청 또는 반복된 동일 실패 뒤 관찰 힌트를 제안한다. 힌트 사용에 감점하지 않는다.

## 4. 장면별 상세 설계

### 1장 물 붓기와 모양

**첫 장면:** 길쭉한 그릇과 넓은 그릇, 같은 양을 담은 두 정량 주전자를 보여준다. “같은 양을 담으면 모습도 같을까?”를 묻는다.

**조작:** 주전자를 그릇 위로 옮긴 뒤 손잡이를 누르고 있으면 물이 흐른다. 손을 떼면 멈춘다. 각 주전자에 준비된 양까지만 붓고 물통과 주전자의 양은 서로 연동한다. 대체 버튼은 같은 양을 자동으로 붓는다.

**관찰:** 수위는 그릇 폭에 따라 달라진다. 물줄기와 출발·도착 용기의 양을 함께 표현한다. 그릇을 바꾼 얼음은 원래 모양을 유지한다. 전후 겹치기에서 모양 차이를 비교한다.

**완료:** 같은 양의 물을 다른 그릇에 담은 장면, 얼음을 옮긴 장면, 젖은 자국의 시간 변화 기록을 확보한다. 계속 누른 시간이나 정교하게 부은 정도는 평가하지 않는다.

**주의:** 모든 그릇에 동일 수위 비율을 채우고 “같은 양”이라고 표시하지 않는다. 단순 2D 직사각 단면 모형을 사용하고 양과 수위의 관계를 일관되게 계산한다.

### 2장 개인 관찰로 상태 설명

1장에서 만든 장면 카드가 카드 보관함에 나타난다. 카드에는 대상, 조작 전후 모습, 실험 번호가 표시된다. 학생은 카드 두 장을 겹치거나 나란히 놓은 뒤 물의 상태와 관찰 근거를 연결한다.

틀린 분류는 즉시 튕겨내지 않고 임시로 놓을 수 있다. “관찰과 맞는지 확인”에서 해당 장면을 재생하고 선택을 바꿀 기회를 준다. 사례를 여러 번 찍어 맞히는 방식이 되지 않게 수정할 때 근거 장면을 선택한다.

필수는 물·얼음·공기로 간 물 3개와 서로 다른 생활 사례 2개다. 추가 생활 사례 1개는 선택 활동으로 둔다. 천이나 빨래 자체를 수증기로 분류하지 않게 대상 영역과 이름을 명확히 표시한다.

### 3장 예상선과 실제 변화 겹치기

처음 물과 무게를 기록한 뒤 용기 옆 눈금에 예상선을 끌어 표시한다. 숫자 입력/방향 버튼도 제공한다. 예상은 얼리기를 시작하면 잠그며 “처음 생각”으로 남긴다.

냉각 도구를 놓고 재생하면 수면이 점진적으로 올라가며 얼음의 표현으로 바뀐다. 가열하면 원래 물의 높이로 돌아간다. 실험은 흘림·증발이 없는 비교 조건이다. 화면의 냉각 속도는 실제 얼음 생성 속도를 재현하는 값이 아니다.

전후 겹치기는 처음 외곽선·예상선·실제 결과를 서로 다른 선 형태로 표시한다. 무게 변화가 없는 것을 관찰한 뒤 “높이 / 무게 중 무엇이 달라졌나”를 기록한다.

완료 조건은 처음·얼린 뒤·녹인 뒤 기록과 한 번의 근거 비교다. 예상값의 근접도는 완료 조건에 넣지 않는다.

### 4장 공간을 남기는 배관 실험

학생은 채움 양을 정하고 얼음이 차지할 공간을 예상해서 표시한다. 냉각 후 얼음이 남은 공간으로 확장되는 단면을 보여준다. 공간이 부족하면 경계선 밖으로 필요한 공간을 해칭으로 표시한다. 파열 폭발 연출은 사용하지 않는다.

다른 채움 조건 두 개를 같은 시작 시점에 맞춰 나란히 재생한다. “15 이상 차이”를 학생에게 요구하는 기존 방식은 없앤다. 시각적으로 비교 가능한 조건 차이를 내부적으로 판단하고, 너무 비슷하면 “차이를 보기 쉽게 물의 양을 더 바꿔 볼까?”라고 제안한다.

완료하려면 공간 부족을 보이는 기록과 여유를 남긴 기록을 비교하고, 사용할 조건과 빈 공간 근거를 선택한다. 처음부터 여유가 있는 조건을 만들었다면 비교용으로 채움을 늘려 관찰할 수 있다. 실제 배관 안전 기준으로 일반화하지 않는다.

### 5장 내 물그림 시간 기록

A에 그린 물그림을 B에 같은 모양으로 복사한다. B는 같은 영역에 더 많은 물을 묻힌 비교 조건이다. 획의 모양이나 그린 속도는 건조율에 임의로 연결하지 않는다.

첫 비교 전 “어느 쪽이 먼저 달라질까?”를 예상한다. 재생·멈춤·빠르게 보기로 변화를 관찰하고 원하는 때 “장면 남기기”를 누른다. 처음 장면은 자동 기록한다. 다른 모습이 나타난 중간과 나중은 학생이 선택한다. 내부 기록 적합성은 시간 숫자가 아닌 물자국의 시각적 차이로 판단한다.

기록 카드는 **실제 그림 + 가상 경과 시간 + 물의 양 조건**으로 만든다. 카드 두 장을 선택하면 나란히 비교하거나 덧겹쳐 볼 수 있다. 카드 선택 시 “기록 보기”로 전환하며 현재 실험을 되돌리지 않는다. “새 실험”에서만 처음 상태로 다시 시작한다.

그림을 고치면 새 실험 번호를 부여한다. 이전 기록은 연구노트에 남기되 새 그림의 완료 증거로 사용하지 않는다. 핵심 완료는 처음·중간·나중 비교, 먼저 마른 조건 확인, 물의 행방 설명이다.

### 6장 실제 확대 렌즈

무가열 대조 실험을 먼저 한 번 기록한다. 다음 실험에서 B의 가열 조건을 정하고 동일 시간으로 두 용기를 비교한다. 실행 도중 조건을 바꾸면 실험을 멈추고 새 시험으로 시작한다. 이전 시험의 수위·관찰·판정을 새 조건에 섞지 않는다.

렌즈를 A 표면, B 물속, 수위 눈금 위로 옮기면 해당 지점의 확대 장면이 나타난다. 손가락에 가려지지 않도록 확대창은 접촉 위치의 위쪽에 띄우고 가장자리에선 자동 반전한다. 렌즈는 실제 관찰 요소를 확대하며, 보이지 않는 수증기를 빛나는 입자로 보여주지 않는다.

A의 즉각적인 증발 자체를 눈으로 보이게 꾸미지 않는다. 대신 기록 속 수위가 줄어든 것을 확대 비교하게 한다. B는 물속에서 반복되는 기포를 보여준다. 표면·물속·수위 관찰은 실제 그 조건의 장면 기록과 연결돼야 한다.

### 7장 부분 닦기와 다시 생기는 물방울

**대표 경험:** 손가락이 지나간 부분의 물방울만 사라지고, 시간이 지나면 그 부분에 물방울이 다시 생긴다.

동일한 두 밀봉 용기 A/B를 놓는다. 이름은 고정하고 냉각팩을 어느 용기에 뒀는지로 조건을 표시한다. 컵 자체의 색이나 모양은 바꾸지 않는다. 물방울을 닦으면 닦은 구역을 짧은 외곽선으로 알려준다. “이 부분을 다시 관찰”을 선택하면 비교 대상 영역이 고정된다.

필수 흐름은 다음과 같다.

1. 물방울의 출처를 예상한다. 예상은 수정 가능하며 최초 선택은 보존한다.
2. 두 용기를 밀봉하고 표면을 닦아 처음 상태를 기록한다. 전체 닦기 대체 버튼도 제공한다.
3. A만 차갑게 한 동일 시간 비교를 기록한다.
4. A의 일부를 다시 닦고, 닦은 자리에서 재생성된 장면을 기록한다.

냉각팩을 B로 옮겨 조건을 교환하는 활동은 심화 선택으로 둔다. 실행 시 두 용기를 닦고 동일한 시작 상태로 새 시험을 시작한다. 냉각팩 이동 즉시 A의 기존 물방울이 사라지는 연출은 금지한다. 가상 조건 준비 시간을 압축했음을 안내한다.

밀봉·재닦기만으로 물방울 출처를 완전히 증명했다고 단정하지 않는다. 차가운/실온 대조와 원리 설명을 함께 사용한다. 무게는 용기와 겉면 물방울의 합이며, 닦아낸 물은 저울 밖으로 제거된 것으로 처리한다. 닦기 직후 무게가 그대로 증가하는 모순을 만들지 않는다.

### 8장 내 가설을 증거로 설명

초기 가설은 “안의 물이 밖으로 나왔다 / 공기 중 수증기가 물방울이 됐다 / 아직 모르겠다”로 둔다. 정답 문장 조각만 나열해서 순서를 맞히는 기존 구조를 바꾼다.

학생은 실제 실험 카드에서 두 가지 서로 다른 증거를 골라 가설에 연결한다. 예: 밀봉 후 생성, 차가운/실온 차이, 재닦기 뒤 재생성. 같은 장면을 두 번 선택하는 것은 두 증거로 세지 않는다. 부족하면 해당 실험으로 돌아갈 수 있으며 기존 카드와 초안은 보존한다.

새 상황은 차가운 음료병과 실온 음료병을 함께 제시한다. 예상 후 시간 관찰로 확인하고 “내 생각이 유지됨 / 바뀜”을 고른다. 최종 설명은 `공기 중 수증기 → 차가운 표면에서 → 액체 물방울`과 실제 증거를 연결한다. 짧은 선택형 설명을 제공하되 자유 입력은 필수로 두지 않는다.

완료는 적절한 최종 설명, 서로 다른 증거 2개, 새 상황의 예상·관찰 비교다. 초기 오답이나 “모르겠다” 선택에 불이익을 주지 않는다.

### 9장 흐름을 보고 고치는 공방

**첫 화면:** 기존 부품 5개를 넓은 작업대에 놓는다. 부품의 입구/출구와 물방울이 떨어지는 위치를 읽을 수 있게 한다. 고정 정답 좌표를 알려주는 그림자는 사용하지 않는다.

**조작:** 부품 이동, 경사판 끝 손잡이로 기울기 조절, 냉각 켜기/끄기. 손잡이는 48px 이상이며 범위 슬라이더와 방향 버튼을 대체 조작으로 제공한다. 스냅은 사용자 정렬을 보조하되 연결 오차를 전부 제거하지 않는다.

**시험:** 1회 시험은 고정 길이의 가상 관찰이다. 냉각판에서 물방울이 생겨 부품 사이를 이동하고, 빗나간 것은 바닥의 손실 구역으로 떨어진다. 물통 수위가 결과와 함께 증가한다. 첫 실패 지점뿐 아니라 통과량과 손실 위치를 보여준다.

**수정:** 시험 중은 관찰만 하고, 부품을 잡으면 일시정지와 “배치를 바꾸고 새 시험”을 제안한다. 수정 후 새 시험은 동일 조건에서 시작한다. 직전 결과는 “이전 시험”으로 남기며 현재 배치의 결과처럼 표시하지 않는다.

**비교:** 이전/현재 두 설계를 같은 시점에 재생한다. 바꾼 부품을 윤곽선으로 표시하고 학생은 “무엇을 바꾸었나 / 어디서 덜 샜나”를 선택한다. 시험 이력은 실제 설계 스냅샷과 연결한다.

**완료:** 서로 다른 설계의 시험 2개, 한 가지 이상 변경점과 결과 비교, 현재 설계와 일치하는 최신 유효 시험, 냉각 및 전체 물길 연결, 최종 수집 지수 60 이상을 기본값으로 한다. 60은 학습용 제안 임계값이며 학생 사용 검증 후 조정한다. 첫 설계부터 성공해도 다른 조건과 비교하여 원래 설계가 더 좋다는 결론을 인정한다. 수집량을 반드시 증가시켜야만 완료되는 조건은 두지 않는다.

### 10장 기록으로 진단하는 코어

학생이 확정한 장치를 복제해서 코어에 연결한다. 원본 설계는 수정하지 않는다. 최초 진입 시 단일 고장 1개를 선택하고 저장한다. 새로고침으로 고장이 바뀌지 않게 한다. 교사는 미리보기에서 유형을 선택할 수 있다.

| 고장 | 처음 보여줄 증상 | 참고 기록 | 가능한 조작과 검증 |
| --- | --- | --- | --- |
| 냉각 중단 | 물길은 연결돼 있지만 새 물방울이 생기지 않음 | 7~8장 차가운/실온 비교 | 냉각 상태 조사·변경 후 생성 재확인 |
| 연결 어긋남 | 물방울은 생기고 중간에서 바닥으로 떨어짐 | 9장 수정 전후 기록 | 실제 어긋난 부품을 옮겨 손실 감소 확인 |
| 얼음 공간 부족 | 별도 저장 구역의 물이 얼며 여유 공간이 사라짐 | 3~4장 공간 비교 기록 | 녹인 뒤 채움 양을 낮춰 재냉각 비교 |

공간 부족 고장은 별도 냉각 저장 구역에서만 발생한다. 응결용 냉각판을 차갑게 하는 것과 물을 얼리는 조건을 같은 것으로 표현하지 않는다. 이 유형은 별도 모형과 과학 검토를 통과한 뒤 활성화하며, 첫 구현은 냉각 중단·연결 어긋남 두 유형으로 완성한다.

학생에게는 증상만 제시하고 “어디부터 살펴볼까?”를 묻는다. 가설 → 관련 기록 선택 → 조작 → 재시험 순으로 해결한다. 잘못된 조작에도 자연스러운 결과를 보여주고 되돌리기를 제공한다. 예를 들어 연결을 고쳐도 냉각이 꺼져 있으면 새로운 물은 생기지 않는다.

완료 조건은 증상에 맞는 원인 확인, 관련 기록 사용, 실제 수정, 수정 후 물 도착이다. 밸브는 물의 전달량을 조절하고 막힘/연결 상태가 결과에 반영된다. 마지막 레버는 물 도착 후 수행하는 성취 동작이며 숫자 90 맞추기 과제로 제시하지 않는다.

엔딩에는 “내가 예상한 것 / 확인한 증거 / 바꾼 부분 / 달라진 결과”를 실제 장면으로 보여준다. 완료 횟수보다 탐구 과정이 보상으로 남는다.

## 5. 디지털 연구노트

연구노트는 장면 카드와 비교 기록을 저장한다. 미션별 정답 문장 목록만 보여주는 현재 방식을 확장한다.

각 카드: 실험 번호, 장면 그림, 관찰 조건, 가상 경과 시간, 학생이 선택한 관찰 영역, 연결한 설명. 같은 시간의 조건 비교와 같은 조건의 시간 비교를 구분한다.

- 카드 누르기: 그때의 모습을 복원한 읽기 전용 기록 보기.
- 두 장 선택: 비교 가능한 조건인지 확인한 뒤 나란히 보기/겹치기.
- 새 실험: 원본 기록과 분리된 새 trial 생성.
- 잘못 찍은 기록: 미션 증거로 채택하지 않고 다른 기록으로 교체 가능.
- 기록 중복: 같은 시점·같은 조건을 여러 번 찍으면 기존 카드를 갱신하거나 중복임을 알려준다.

사진은 기기 카메라 사진이 아니라 가상 실험 장면이다. 원본 상태로 재구성한 작은 썸네일을 사용하고 외부로 전송하지 않는다.

## 6. 시뮬레이션과 판정 설계

### 실험과 기록의 시간 분리

실험은 앞으로 진행하는 `elapsed`를 갖는다. 기록 보기는 `playhead`로 과거 장면을 탐색한다. 기록의 playhead 변경은 현재 실험의 상태·완료 여부·무게를 바꾸지 않는다. 과거 기록 보기에는 지속적으로 “기록 재생” 표지를 표시한다.

일반 실험 흐름은 `준비 → 예상 → 실행/멈춤 → 기록 → 비교 → 설명`이다. 모든 장면에 별도의 화면 6개를 만들지 않고 한 작업대에서 필요한 조작만 순차 노출한다.

### 공방의 부분 손실 모형

기존의 완전 연결/0 판정을 접속 면의 겹침과 방향을 이용하는 전달 비율로 확장한다.

- 냉각이 켜진 동일 조건의 생성 지수는 100, 꺼지면 0이다. 냉각 온도별 생산량은 이번 범위에 넣지 않는다.
- 각 연결부는 입사 물줄기의 폭과 받는 입구가 겹치는 비율 `capture ∈ [0,1]`을 계산한다. 높이·방향이 물의 진행과 모순이면 0이다.
- 경사판의 하향 기울기는 이동 시간에 영향을 준다. 기존 임의의 20도 최적 수집량은 제거한다. 상향/수평은 고임 또는 반대 방향 손실로 일관되게 표현한다.
- `out = in × capture`, `lostAtNode = in − out`. 총수집+총손실+시험 종료 시 남은 물은 생성 지수와 같아야 한다.
- 고인 물을 손실로 합치지 않는다. 기본 시험 길이는 정상 연결된 물이 물통에 도착하도록 정하고, 남은 물이 있으면 “장치에 남음”을 따로 표시한다.
- 부품을 조금 옮겨 접속이 조금 나아지면 결과도 연속적으로 달라진다. 완전히 끊긴 연결에서는 0이 타당하다.
- 화면의 물방울 수는 렌더링용 표본이다. 판정은 순수 모형 값으로 계산하며 기기 프레임 수나 애니메이션 종료 이벤트에 의존하지 않는다.
- 실제 생산량·열역학·배관 공학을 예측하는 모형으로 표기하지 않는다.

### 응결의 부분 닦기 모형

정규화된 용기 표면 좌표의 물방울과 생성 시점을 저장한다. Pointer 경로 주변 반경 안의 물방울만 제거한다. 닦은 영역은 작은 격자 마스크 또는 단순화된 경로로 보존한다. 찬 표면 조건과 경과 시간이 유지되면 닦은 영역에도 새 물방울이 생성된다.

무게를 표시할 때는 내부 액체+용기+현재 겉면 물방울의 질량 합으로 계산한다. 모형상 물방울 개수와 질량의 대응은 동일 버전에서 일관돼야 한다. 이미지에 보이는 물방울만으로 실측 질량을 계산한다고 설명하지 않는다.

## 7. 데이터와 저장

기존 KEY를 유지하되 `schemaVersion: 2`와 버전별 migration을 추가한다. 기존 버전을 곧바로 기본 상태로 버리지 않는다. 기존 수업 완료는 보존하며 새 방식의 추가 증거가 없다는 이유로 잠금을 되돌리지 않는다.

새 구조의 핵심은 다음과 같다.

```text
schemaVersion: 2
activities.version: 2
experiments[sceneId]: activeTrialId, trials[], selectedRecordIds[]
trial: id, modelVersion, sceneId, conditions, initialState, elapsed,
       prediction, events[], snapshots[], result, status
snapshot: id, trialId, elapsed, sceneState, observationRegion, conditionSignature
comparison: recordIds[], changedVariable, observation, conclusion
workshop: draft, trials[], confirmedDesign
collectorResult: generated, collected, lost, retained, links[], flowEvents[], signature
final: faultId, faultSeed, hypothesis, evidenceIds[], workingDesign, tests[], resolved
```

- `sceneState`는 해당 장면의 최소 JSON 상태만 저장한다. DOM, 전체 HTML, base64 캡처를 localStorage에 넣지 않는다.
- 그림 획은 assetId로 참조하고 trial마다 복제하지 않는다. 그림 수정은 새 assetId를 만들고 이전 기록의 참조는 유지한다.
- 과거 기록은 `modelVersion`과 확정 결과로 재생한다. 새 모형으로 과거 결과를 몰래 재계산하지 않는다.
- 시험 시작·일시정지·닦기 종료·그리기 종료·기록 확정·설계 확정·장면 이동에 저장한다. 포인터 이동마다 동기 저장하지 않는다.
- 저장 실패 시 현재 메모리 상태를 유지하고 알림을 표시한다. 성공처럼 안내하지 않는다.
- 구버전의 수치 기록은 “이전 방식 기록”으로 읽을 수 있게 남기며 존재하지 않는 썸네일·가설·조작 이력을 만들어내지 않는다.
- 구버전 공방 완료 장치는 보존한다. 새 공방 모형에서 재시험하는 것은 별도 새 활동으로 처리한다.
- 장면당 비채택 시험 8개를 기본 보존하고, 채택 증거·확정 설계·최종 문제의 참조는 우선 보존한다. 삭제 전 참조 관계를 검사한다. 상태 직렬화 목표는 1MB 이내다.

## 8. 구현 모듈과 순서

기존 코드를 점진적으로 수정한다. 아래 신규 모듈은 역할 경계를 위한 제안이며 초기에 불필요하게 잘게 나누지 않는다.

| 대상 | 변경 |
| --- | --- |
| app.js / v2.css / activities.css | 공통 실험 작업대, 하단 조작 띠, 캐릭터 축소, 집중 보기 |
| activity-model.js | 각 실험의 준비·실행·기록 상태, 조건 분리, 근거 기반 완료 |
| activities.js | 붓기·렌즈·부분 닦기·기록 비교 UI 연결 |
| domain.js | 부분 전달/손실 모형, 실험 signature, 설계 완료 판정 |
| workshop.js | 물방울 경로, 입출구 시각화, 이전/현재 비교, 코어 고장 진단 |
| state.js | v1→v2 migration, 기록·설계 참조와 무결성 검증 |
| journey.js | 정답 노출 안내 제거, 관찰 힌트·실제 기록 보상 |
| 신규 timeline.js | 재생·멈춤·속도와 기록 탐색, 화면 이동 시 타이머 정리 |
| 신규 research-records.js | 장면 스냅샷, 썸네일 재구성, 비교 가능성 검사 |
| 신규 collector-model.js / condensation-model.js | 복잡해질 때 순수 모형을 기존 파일에서 분리 |

### 구현 묶음과 종료 기준

1. **공통 무대·기록 기반:** 화면 구조, trial/snapshot과 저장 migration, 실험/기록 구분. 1024×768에서 결과와 핵심 조작 동시 표시.
2. **대표 경험 9장:** 실제 흐름·부분 손실·설계 비교. 서로 다른 정상 배치를 인정하고 손실 개선이 시각·수치에 일치.
3. **대표 경험 7~8장:** 부분 닦기·재생성·가설과 증거 연결. 닦은 영역과 증거가 재진입에도 보존.
4. **5~6장 시간·렌즈:** 그림 썸네일, 실제 확대와 동시간 비교. 기록 탐색이 실행 상태를 바꾸지 않음.
5. **1~4장과 마지막 연결:** 연속 붓기·공간 비교, 10장 냉각/연결 고장, 개인 기록 엔딩. 시작부터 완료까지 연결.
6. **선택 확장:** 냉각 조건 교환, 10장 공간 부족 고장. 필수 경로 완성 후 별도 과학·수업 검토.

각 묶음에서 관련 자동 검사와 브라우저 회귀를 완료한 뒤 다음 변경을 통합한다. 이번 요청의 산출물은 설계서와 설계 미리보기이며, 위 항목의 앱 구현은 포함하지 않는다.

## 9. 로딩과 성능 설계

- 현재 배경·캐릭터를 재사용한다. 이번 개편의 첫 화면 필수 이미지 요청 증가 목표는 0개다.
- 실험 전용 모듈은 장면 진입 때 로드한다. 첫 화면 JS/CSS 증분 전송량은 압축 후 50KB 이내를 목표로 계측한다. 목표값이지 현재 실측값은 아니다.
- 물방울 표본은 기본 60개 이하, 저성능 기기에서는 30개로 줄인다. 수치 결과는 바뀌지 않는다.
- 렌더는 requestAnimationFrame, 모형은 경과 시간 또는 고정 스텝 기준으로 갱신한다. 백그라운드 전환 시 일시정지하며 복귀 후 시간을 한꺼번에 건너뛰지 않는다.
- 움직임 줄이기는 경로와 단계별 결과를 정적으로 보여준다. 같은 관찰과 완료가 가능해야 한다.
- 썸네일은 원본 JSON에서 필요할 때 생성하고 최근 카드만 메모리에 보관한다. 전체 연구노트 이미지 사전 생성은 하지 않는다.
- 외부 폰트/CDN/API 의존성을 늘리지 않는다. 기존 저장 오류 처리와 장면 정리를 유지한다.

## 10. 검증 기준

### 기능과 모형

- 같은 조건과 seed로 실행한 결과가 프레임 속도와 무관하게 같음.
- 물의 양·수집·손실·남은 양 사이의 모형 보존 관계가 성립함.
- 연결이 부분적으로 겹칠 때 결과가 연속적으로 변화하고, 물이 위로 흐르는 잘못된 연결은 통과하지 않음.
- 닦은 영역 밖 물방울이 보존되고, 찬 표면의 닦은 영역에서 재생성됨.
- 무게가 닦기와 물방울 재생성에 일관되게 반응함.
- 기록 되감기·모형 버전 변경·조건 변경이 이미 확정한 기록을 바꾸지 않음.
- 새 그림·새 조건의 기록을 이전 trial 증거와 섞어 완료할 수 없음.
- 코어 고장은 새로고침 후 같고, 해당 원인을 수정해야 해결됨. 원본 확정 설계는 유지됨.
- v1 저장의 진행·설계·완료가 보존되고 손상된 새 필드만 안전하게 복구됨.

### 조작과 화면

1280×800, 1280×720, 1024×768, 1920×1080, 작은 세로 화면에서 확인한다. 실제 학교 태블릿에서 직접 드래그·문지르기·다중 포인터 중단·회전·주소창 변화도 검증한다.

모든 필수 조작은 키보드/버튼 대체로 완료 가능해야 한다. pointercancel 뒤 잡힌 물체나 막힌 스크롤이 남지 않아야 한다. 두 번째 손가락이 실험을 중복 실행하지 않도록 활성 포인터 하나를 추적한다.

### 학습 경험 관찰

수업 파일럿에서 다음 행동을 관찰한다. 예상 시간은 첫 가설로 2차시 분할 운영을 두고 실제 소요 시간에 맞춰 조정한다.

- 학생이 글 설명을 읽기 전에 변화가 생긴 위치를 찾는가.
- “어느 버튼을 누르래?”보다 “여기를 바꾸면 어떻게 될까?”를 말하는가.
- 공방에서 수정 이유와 달라진 결과를 설명할 수 있는가.
- 컵을 닦은 행동이 어떤 증거가 되는지 말할 수 있는가.
- 기록 되감기를 실제 현상의 역전으로 오해하지 않는가.
- 마지막 문제에서 앞선 기록을 골라 해결에 사용하는가.

1차시는 1~6장의 상태·얼기·시간 비교, 2차시는 7~10장의 응결·설계·진단을 기본 운영안으로 둔다. 선택 심화는 필수 완료와 분리한다. 실제 학습효과나 수업 시간을 구현만으로 보장하지 않는다.

## 11. 화면 미리보기의 범위

동봉 미리보기는 공방·응결·물그림 세 장면의 화면 비중, 조작 위치, 전후 결과 표시를 확인하기 위한 설계 자료다. 공방의 “배치 조정”과 응결의 “닦은 자리”는 실제 드래그/부분 닦기를 대신하는 상태 전환 버튼이다. 물그림은 예시 그림이다. 숫자는 예시이며 판정 모형이나 학습 완료와 연결되지 않는다.

실제 앱 개발에서는 본문의 직접 조작, 저장, 과학 표현, 접근성, 검증 조건을 구현해야 한다. 미리보기의 단순화를 운영 앱의 완료 기준으로 사용하지 않는다.
