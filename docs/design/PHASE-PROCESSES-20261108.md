# 녹이기·끓이기·응결 과정 개편

## 범위와 완료 기준

2장 현장 의뢰의 세 변화를 얼음틀 실험과 같은 준비 → 조건 만들기 → 시간 관찰 → 비교 방식으로 바꾼다. 기존 실험의 물리 모형과 이미지를 재사용하고 엔진·의존성을 추가하지 않는다. 각 변화는 선행 조건과 실제 관찰 기록이 있어야 완료된다. 새로고침·축소 화면·터치·키보드에서도 같은 과정을 수행할 수 있어야 한다.

## 발견한 문제

- 녹이기는 따뜻한 받침을 선택하는 순간 결과가 정해지고 얼음이 녹는 중간 과정이 없다.
- 끓이기는 도구 선택과 시간만으로 발견을 주어 준비한 두 컵, 가열 조건, 관찰한 기포와 물높이의 관계가 약하다.
- 응결은 냉각팩을 붙이면 물방울 그림으로 바뀐다. 처음의 물기를 제거했는지, 어느 면에 새 물방울이 생겼는지, 냉각팩에서 샌 물인지 구별하는 확인이 없다.

## 적용할 과정

| 변화 | 준비와 조건 | 관찰과 완료 |
|---|---|---|
| 녹이기 | 방금 얼린 같은 얼음틀을 실온 준비대에 놓기 | 시간이 흐르며 얼음은 작아지고 녹은 물이 나타남 → 모두 녹은 뒤 같은 틀의 전후 비교 |
| 끓이기 | 같은 두 컵에 같은 양의 물 준비 → B만 가열 | 같은 시간 동안 A·B 물높이와 B 물속 기포를 관찰 → 가열을 멈추고 관찰 기록 비교. 수증기를 흰 김처럼 그리지 않음 |
| 응결 | 두 같은 판의 겉면 닦기 → B판 뒷면만 냉각 | 같은 시간 뒤 A는 마른 상태, B 앞면에는 새 물방울 → B 앞면을 다시 닦고 그대로 냉각하며 기다림 → 다시 맺히는 물방울 확인 |

가열하지 않은 A에서도 표면 증발은 일어난다. 끓을 때 물이 전부 사라져야 하는 것으로 표현하지 않는다. 응결 실험은 공기 중 수증기가 충분한 조건의 모형이며 공기 중 수증기 자체는 눈에 보이지 않는다. 시간 손잡이는 실제 분·초나 정확한 실험 소요 시간을 뜻하지 않는다. 가열 조작은 가상이며 실제 가열은 선생님과 함께 한다.

## 재사용과 저장

- `freeze-tray.js`의 동일한 여섯 칸과 얼음틀 이미지를 녹이기의 중간 상태와 전후 비교에 확장한다.
- `activity-model.js`의 `heatingTrial`, `dewTrial`을 각각 두 컵과 판 위 물방울 관찰에 사용한다. 7장의 닦기 → 비교 → 다시 닦아 확인하기 방식을 응결에 적용한다.
- 기존 `fieldwork.chapters[2].moves`에 각 변화의 단계·시간·완료 근거를 기록한다. 2장에 한해 정리 시 허용하는 키 개수를 24개로 늘려 전체 12개 과정 필드와 기존 시도 기록을 보존한다. 저장 키와 스키마 버전은 유지한다.
- 이전 버전의 실제 발견·도장은 유지한다. 새 과정의 발견은 비교 완료 단계와 충분히 지난 시간을 함께 검사한다.
- 상태 규칙은 `fieldwork-model.js`에, 화면과 공통 시간·드래그·수명 관리는 `transform-process.js`에 둔다. `field-transform.js`는 네 변화의 진행과 화면 연결만 담당한다.

## 검증 계획

순서 건너뛰기, 잘못된 시간, 시간 되돌리기, 비교 전 완료, 이전 발견 손실, 저장 정리로 필드가 잘리는 문제를 단위 테스트로 검증한다. 브라우저에서는 네 변화 전체 흐름, 각 중간 단계 새로고침, 마우스·버튼·키보드·터치 에뮬레이션을 확인한다. 1920×1080, 1280×800, 1024×768, 1024×600, 915×412, 375×812에서 실제 화면을 촬영하고 조작부 가림과 잘림을 확인한다. 실제 학교 태블릿과 iOS Safari는 미실측이다.
