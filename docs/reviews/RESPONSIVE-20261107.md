# 물길 탐험 이미지·반응형 보강 (2026-11-07)

## 변경 범위
6 waterchange만 변경했다. 커밋·배포·패키지 설치는 하지 않았다. 저장·완료 판정·기존 학습 흐름은 변경하지 않았다.

- 9·10장 기존 그림과 장치 에셋은 유지하고, 실험판 배경 대비를 높여 배경과 장치가 뒤섞이지 않게 했다.
- 좁은 화면에 축소된 캔버스 글씨를 보완하는 DOM 부품 이름·순서 범례를 추가했다.
- 9장 작은 화면의 상태 변화 순서를 2열로 정리하고 부탁·피드백 여백을 조정했다.
- 높이 560px 이하 가로 화면에서는 장치 카드 내부에 잘리는 작은 스크롤 대신 페이지 스크롤로 전체 그림과 조작부에 도달한다. 한 화면에 모두 들어간다는 의미가 아니다.
- 실패 위치의 붉은 표지 설명을 장치 이름과 겹치지 않는 오른쪽 위로 옮겼다.
- 기존 이미지 자산이 충분하여 새 생성형 이미지나 외부 다운로드는 추가하지 않았다.

## 검증
- 구문 검사 통과.
- 전체 Node 테스트 160개 통과(오프라인 빌드 테스트 포함).
- node scripts/build.mjs --out tmp/responsive-20261107 성공. 기존 dist는 교체하지 않았다.
- 별도 4336 포트, 새 Chrome 탭, 학생 저장과 분리된 교사 시연으로 점검했다.
- 1920×1080, 1280×800, 1024×768, 1024×600, 830×515, 915×412, 768×1024, 390×844에서 9·10장 화면을 검사했다.
- 측정한 주요 조작 버튼은 48px 이상이고 가로 페이지 넘침과 실패한 DOM 이미지는 없었다. 캔버스 자산도 표본 캡처에서 정상 표시를 확인했다.
- 10장 세로 화면의 카드 scrollHeight 차이 3~4px는 테두리/그림자 수준이며, overflow visible로 내용은 잘리지 않는다.
- 최종 560px 분기 변경은 10장에서 830×515 포함 재검증했다. 9장은 500px 분기 상태의 8종 측정과 915×412 실제 캡처로 확인했고, 560px로 확장한 뒤 830×515의 별도 재캡처는 하지 않았다.
- 대표 증거: screenshots/responsive-20261107/core-desktop.jpg
- AGENTS.md 지시에 따라 graphify update . 실행.

## 제한과 후속
실기기 터치, 학교 네트워크, 전체 학생 1~10장 완료 경로는 이번 범위에서 재실행하지 않았다. 9장 빠른 연속 수정 시 완료 조건, 이전 공방 기록 마이그레이션, 움직임 줄이기 관찰 시간, 10장 고장 선택 규칙은 이전 검토의 별도 로직 과제로 남겼다.
