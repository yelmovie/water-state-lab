# 태블릿 상호작용 소스 감사 · 2026-10-24

초기 감사는 읽기 전용 소스 확인이었다. 이후 시간 드래그 수정에 대해 단일 격리 Chrome으로 실행한 검증을 아래에 추가했다. 코드 감사 결과와 브라우저 실측 결과를 구분한다. 실제 태블릿 하드웨어는 사용하지 않았다.

## 실제로 실행되는 화면 경로

- `app.js`의 `experimentShell()`은 1~8장을 `activityView()`, 9장을 `workshopView()`, 10장을 `finalView()`로 연다.
- `activityView()`는 `inquiryView()`가 있으면 이를 사용한다. 1장 붓기, 2·5·6·7·8장은 inquiry 화면이 실제 경로다. legacy 화면은 1장 얼음·천, 3·4장에 사용된다.
- Phaser가 준비되면 해당 DOM 실험 그림에 `.phaser-replaced`를 붙여 숨기고 Canvas가 조작을 담당한다. 따라서 legacy 5·7·8장에 구현된 드래그·시간 슬라이더가 있다고 실제 활성 화면에도 있다고 판단하면 안 된다.
- 실험 완료 버튼은 `routeAction()`이 가로채 각 장의 현장 의뢰를 먼저 연다. 현장 완료 후 원래 버튼 동작을 실행한다. 10장 마지막 레버도 현장 의뢰 후 엔딩으로 연결한다.
- 현장 의뢰는 Phaser를 사용하지 않는다. `fieldwork.js`의 Canvas, Pointer Events, 공통 상태 모형으로 작동한다.

## 우선 발견 사항

### P1 · 실제 시간 슬라이더가 다른 화면 구현에 가려짐 — 수정 진행 중

`inquiry.js`의 기존 `controls()`는 시간 재생, +25 진행, 빠르기, 기록 버튼만 제공했다. 반면 시간 슬라이더는 실제 사용하지 않는 legacy 화면에도 남아 있었다. 1·5·6·7·8장의 활성 controls에 시간 드래그를 통합해야 사용자 요구가 충족된다. 재생은 선택적 보조 동작으로 남길 수 있다.

시간 입력·앞으로 버튼·자동 재생은 같은 사전 조건을 확인해야 한다. 5장 예상, 7장 양쪽 닦기·밀봉·예상, 8장 설명 연결·예상·두 병 닦기 같은 조건이 경로에 따라 우회되면 관찰 순서가 달라진다. 관찰 기록을 보는 되감기와 진행 중 실험 시간을 분리하는 기존 원칙은 유지한다.

### P1 · 현장 8에서 먼저 성공하면 완료 이유를 알 수 없음

`fieldwork-model.js`의 `fieldReady(8)`은 실패 시험 1회 후 성공 시험을 요구한다. 그러나 화면 목표는 판 냉각과 받이 배치를 먼저 안내한다. 처음부터 올바르게 조립해 시험하면 물이 모였는데 완료 버튼은 잠겨 있다. `fieldProgress()`의 숫자만으로 실패 기록이 필요하다는 것을 알 수 없다.

권장: 차갑게 하지 않은 판에서 먼저 관찰하는 단계를 명시하거나, 완료 가드를 실제 학습 목표에 맞게 조정한다. 모델 조건을 유지한다면 무엇을 아직 비교하지 않았는지 구체적으로 안내해야 한다. settings_quality 작업자에게 전달했다.

### P1 · 8장 Phaser 대체 화면에서 새 병의 관찰 그림 누락

`inquiry.js`의 `explanationActivity()`는 증거 그림과 설명 체인을 표시하지만, 체인 완성 뒤 새 병 그림과 닦을 대상을 렌더링하지 않는다. `phaser-scenes.js`의 `explainScene()`에서만 실제 병 두 개를 그린다. Phaser가 로드되지 않은 경로에서는 버튼으로 닦고 시간·기록을 진행해 완료할 수 있어도, 관찰할 물체가 없다.

권장: 활성 inquiry 화면에 최소한의 병 비교 그림·문지르기 대상을 제공하고 Phaser가 성공할 때만 해당 그림을 대체한다. legacy 8장 그림을 수정하는 것으로는 활성 경로가 고쳐지지 않는다.

### P2 · 작은 Canvas 손잡이의 터치 영역 — 실측 전 추정

Phaser 예상선 손잡이 반경 20, 물높이·기울기 반경 24, 밸브 반경 23이다. 논리 크기 720×330이 기본 CSS 높이 300px로 축소되기만 해도 예상선은 약36px, 밸브는 약42px이다. 작은 태블릿에서는 더 작아질 수 있다. 3·4장은 주변의 큰 조작 zone이 일부 보완하지만 9장 기울기·10장 밸브는 손잡이를 직접 잡아야 한다.

권장: 시각 크기를 변경하기 전 interactive hitArea를 확대한다. 인접 부품이 터치를 가로채는지는 906×755·1280×800에서 실측해야 한다. settings_quality 작업자에게 전달했다.

## 확인한 방어 코드

- 현장 Canvas는 활성 `pointerId`를 기억하고 `pointercancel`에서 놓기 판정을 건너뛴다.
- 공통 DOM 드래그와 inquiry 드래그는 pointer capture를 사용한다.
- 현장 선 연결은 드래그뿐 아니라 출발·도착을 차례로 누르는 방법도 지원한다.
- 현장 도구 배치도 물체를 누른 뒤 놓을 곳을 누르는 대체 입력이 있다.
- 실험 기록과 현재 장치가 다른 경우, 9장 완료는 현재 배치로 다시 시험하기 전까지 잠긴다.
- 현장 완료 버튼은 클릭 처리에서도 `fieldReady()`를 재확인한다.

## 추가 브라우저 검증

`scripts/tablet-interactions.py`를 소스 서버 `http://127.0.0.1:4324`에서 실행했다. 기존 실험 흐름을 유지하면서 시간 입력은 JS 값 지정이 아닌 실제 마우스 드래그로 검사했다. 현장 의뢰 자체는 별도 스크립트의 범위이며, 본 실험 흐름의 1·2·10장 현장 도장은 명시적 준비 상태로 제공했다.

- 주전자를 놓자마자 두 그릇이 채워지는 동작, 얼음 이동, 혼합 Canvas·버튼 분류, 자유 그림, 세 시간 기록, 새로고침 보존, 부분 닦기와 재응결, 새 병의 명시적 기록, 공방 부품 이동과 저장을 통과했다.
- 5장 1280×800, 7장 768×1024, 8장 미리보기 캡처를 육안으로 확인했다.
- 첫 실행의 10장 기존 흐름에서 `diagnosis-evidence-4` 클릭이 `compact-guide`의 `concept-replay` 버튼에 가로막혔다. 1280×800에서 30초 재시도 끝에 실패했으며 강제 클릭으로 우회하지 않았다. `time-drag/failure.png`와 최초 `results.json`에 실패 증거를 보존했다.

### 수정 후 집중 재검증 — 통과

개념 다시 보기 버튼을 힌트 안으로 이동하고 10장 증거 버튼을 캐릭터와 분리한 뒤, 같은 스크립트의 `QA_MODE=final`로 해당 흐름만 재검증했다. `results-final.json`: 통과, 페이지 오류 0, 프로세스 종료 코드 0.

- 9장 경사 손잡이를 보이는 원 밖 32논리px에서 잡아 움직였을 때 기울기가 변경되고, 가까운 깔때기 위치는 유지됐다.
- 10장 냉각·연결 고장 두 경우 모두 가려졌던 증거 버튼 실제 클릭, 근거 선택, 수리, 코어 연결을 통과했다.
- 밸브도 중심 왼쪽 32논리px에서 잡아 위로 당기면 100으로 열렸다.
- 방울이 힌트 → 개념 다시 보기 → 영상 닫기 → 힌트 닫기가 작동했다.
- 두 고장 모두 물 보내기, 마지막 레버, 엔딩, 새로고침 후 저장 유지까지 통과했다.
