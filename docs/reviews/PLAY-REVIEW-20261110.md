# 실사용 플레이 점검 (2026-11-10)

방울이의 물길 탐험(4학년 1학기 「물의 상태 변화」)을 학생처럼 처음부터 끝까지 직접 플레이하며 점검하고 고친 기록이다.

## 점검 범위

- 기준: 운영 배포 커밋 `aaca008`. 빌드 결과를 공개 주소(https://water-state-lab.pages.dev/)와 해시로 대조해 346개 중 345개가 같았다. 다른 하나는 빌드 시각이 들어가는 `build-info.json`이다.
- 방법: `dist/`를 로컬 서버(5206)에 올리고 Playwright(크롬 헤드리스)로 직접 조작했다. 저장값을 고치거나 판정 함수를 부르지 않고, 끌기·문지르기·슬라이더(마우스와 키보드 End·화살표)·스페이스 공격·버튼으로만 진행했다.
- 경로: 타이틀 → 도입 영상 → 지도 → 1~10장 실험 → 현장 의뢰 2·4·10 → 개념 영상 5편 → 지도 악당 5마리 → 엔딩 영상 → 엔딩 화면 → 능력 선택 → 연구 인증서. 고친 뒤 새 빌드로 같은 경로를 한 번 더 처음부터 끝까지 플레이했다.
- 오답 경로: 2장 상태 분류, 2장 숨은 물, 3장 배관 질문, 4장 시험관 고르기, 4장 한파 이유, 5장 마르는 순서·물의 행방, 6장 물의 행방, 8장 설명 순서, 9장 고치기 전 시험, 10장 고장 원인, 4장 셋째 밤 넘치게 담기(통 깨짐 → 다시 채우기).
- 화면: 1280×800에서 약 130장(모든 단계). 1920×1080·915×412에서 지도, 실험 대표 화면, 개념 영상, 엔딩, 인증서.
- 소리: 재생 함수에 기록기를 달아 모든 조작의 효과음·배경음·영상 소리를 기록했다. 모든 음원 파일 107개의 평균·최대 음량과 길이를 ffmpeg로 쟀다.

- 배경 음악은 도입·엔딩·개념 영상과 주민 목소리 재생 중 멈추고, 끝나면 다시 이어진다. 화면 이동 뒤 남는 소리는 없었다. 404·디코딩 오류 없음.
- `play()` 거부는 '클릭 소리가 다음 효과음에 끊김', '영상 시작 때 음악 정지'로 생긴 AbortError뿐이며 의도된 동작이다.

## 남은 문제와 이유

- 주민 목소리: 계획(24줄, 주민 5명 프리셋 배정)은 넘겼고 메인 세션의 모모 생성 파일을 기다리는 중이다. 파일이 오면 `src/npc-audio.js` 경로를 바꿔 적용한다.
- 장 시작 편지를 자동으로 열지 않는 것은 2026-11-08 결정(AUTOPLAY-CERTIFICATE-WATERWAY)이라 그대로 두었다. 제목줄의 주민 얼굴을 눌러야 편지가 열리고, 화면에 이를 알리는 글은 없다.
- 효과음 사이 음량 차이: question(-10 dB)·confirmation_001(-11 dB)이 click(-19 dB)·splash(-30 dB)보다 크다. 코드에서 재생 음량을 따로 주고 있어 실제 차이는 줄지만, 실기기에서 들어 보고 조정해야 한다.
- 개념 영상 소리는 배경 음악보다 약 12 dB 작다. 영상 중에는 음악이 멈춰 겹치지 않는다.
- 실제 터치 기기, 학교 네트워크, 전자칠판 뒷자리 가독성은 확인하지 못했다.
