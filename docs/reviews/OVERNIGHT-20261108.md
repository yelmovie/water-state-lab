## 장별 시각 점검과 유지 이유
- 1–2: 물 옮기기·얼음·분류의 동적 모양과 기존 이미지 자료 유지. 수위/선택을 정적 그림으로 대체하지 않음.
- 3–4: 최근 생성된 시험관·마개·냉동고와 기존 얼기/녹기 부피 비교 유지.
- 5–6: 직접 그린 물그림의 건조와 가열 비커 수위/기포는 동적 자료이므로 유지.
- 7–8: 현재 기본 화면은 이미 생성 컵·냉각팩·음료병을 사용한다. 새 캔으로 이를 전면 교체하지 않고 응결 개념의 생활 사례에 적용했다. 이전 보조 캔 렌더도 개선했다.
- 9–10: 물길 설계와 온실의 상태 변화는 모형 데이터와 연결된 동적 표현을 유지했다.

## 추가 터치 검사 제한
- `chapter-process-qa.mjs touch` 실행은 첫 `[data-measure-action="measure"]` 요소가 숨겨진 상태여서 시간초과했다. 현재 안내 화면은 이미 처음 무게를 표시하고 예상 선택 단계에 들어가 있으므로 기존 스크립트 순서와 불일치한다. 앱 자체 오류로 단정하지 않는다.
- 기존 touch 스크립트 자체는 통과하지 않았다. `chapter-touch.log`, `chapters/report-touch.json`, `chapters/failure.png` 참조. 후속 검사는 현재 안내 흐름의 보이는 예상 버튼부터 시작하도록 시나리오를 갱신해야 한다.
- 세 프로젝트 `git diff --check` 통과(기존 CRLF 정규화 안내만 출력).

## 현재 흐름 터치 재검증: 통과
- 앱 코드는 바꾸지 않고 별도 `output/overnight-20261108/current-touch-smoke.mjs`로 진입 순서만 맞췄다. 실제 보이는 **직접 조작** 버튼을 tap해서 도구를 연다. 이미 처음 무게가 자동 표시된 상태면 숨은 측정 버튼을 누르지 않고 보이는 예상 선택부터 진행한다. force-click이나 DOM click 주입으로 건너뛰지 않았다.
- 1024×600 터치: 얼기→꺼내기→얼음 측정→녹이기→녹은 물 측정→비교 완료(`measure-touch`), 온실 준비→관찰→받이→냉각→물모으기→비교 완료(`greenhouse-touch`) **2/2 통과**. 화면 문제0, 런타임 오류0.
- 증거 `current-touch/report-touch.json`, `current-touch/touch-measure-done.png`, `current-touch/touch-greenhouse-done.png`. 두 완료 화면을 직접 확인했다. 이 두 핵심 흐름 검증을 전10단계 터치 완주로 확대하지 않는다.
