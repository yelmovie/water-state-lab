# 태블릿 실험 무대 복구·검증

2026-10-18. 중단 시점의 Phaser 실험 무대, 연구섬 지도, 탐구 기록과 코어 진단 구현을 이어서 확인했다. 기존 앱과 자료를 보존하고 실행을 막는 화면 문제 및 대체 조작 문제를 수정했다.

## 수정한 문제

- 기존 `v2.css`의 두 열 작업 영역이 새 상하 배치에 남아 실험 무대가 폭 0으로 줄어들었다. `tablet.css`에서 작업 영역을 한 열로 명시하고 안내·실험의 행과 열을 지정했다.
- 초기 숨김 상태의 크기로 Phaser가 계산되어 도구가 매우 작게 표시됐다. 캔버스를 레이아웃 흐름에서 분리하고 ResizeObserver로 실제 무대 크기를 Phaser에 전달한다. 장면 종료 시 관찰자를 해제한다.
- 세로 화면에서 실험 패널의 최소 콘텐츠 폭 때문에 가로로 넘쳤다. 패널의 최소 폭을 0으로 지정해 화면 안에 배치한다.
- 캔버스 분류에서 버튼 분류로 전환하면 이전 카드가 선택된 채로 남았다. 분류 성공 후 선택을 해제해 다음 관찰을 선택한다.
- 캔버스로 교체하면서 가려진 돋보기의 세 관찰 버튼을 도구 패널의 대체 조작에 연결했다.

## 검증

| 항목 | 결과 |
|---|---|
| JavaScript 구문 | 전체 모듈 검사 통과, 마지막 수정 모듈 재검사 |
| 자동 테스트 | 42개 통과. 기존 37개 및 물높이·정량 붓기·지도 경로·발견 별·입력 전환 회귀 검사 |
| 화면 | 지도와 1~10장 × 6개 크기, 66개 통과 |
| 화면 크기 | 1280×800, 1280×720, 1024×768, 1920×1080, 915×412, 375×812 |
| 가로 넘침·스크립트 오류·HTTP 오류 | 화면 검사에서 0개 |
| 실제 조작 | 주전자 연속 붓기, 얼음 이동, 천 적시기, 분류 카드 이동·버튼 전환, 물그림, 부분 닦기, 공방 부품 이동 |
| 기록 | 첫 연구 기록 획득, 그림 세 시점 기록, 기록 탐색 시 현재 시간 보존, 새로고침 후 그림·부품 위치 복원 |
| 응결 | 닦은 일부 영역만 제거되고 같은 자리에 물방울이 다시 생기는 것 확인 |
| 코어 | 냉각 중단·연결 어긋남 각각 원인 선택 → 증거 → 수리 → 재시험 → 밸브 → 레버 → 엔딩·새로고침 복원 |
| 대체 조작 | 분류 버튼과 돋보기 세 관찰 버튼 실행 확인 |
| 빌드 | 정적 빌드와 로컬 Phaser·MIT 라이선스 포함 확인 |

브라우저 검사는 분리된 임시 Chrome 컨텍스트와 4320/4321 주소를 사용한다. 코어 검사는 유효한 이전 설계·연구 기록을 준비한 상태에서 두 고장 유형을 각각 재현했다. 앞선 1~8장의 전체 완료 규칙은 자동 테스트에서 확인하며, 브라우저에서 모든 장을 순서대로 완주했다고 주장하지 않는다.

좁은 세로 화면은 세로 스크롤을 허용한다. 낮은 가로 화면은 패널 내부 스크롤을 사용한다. 실제 학교 태블릿의 하드웨어 터치·성능·수업 효과는 이번 로컬 Chrome 검사 범위에 포함하지 않는다.

## 실행과 기록

```powershell
npm run check
npm test
npm run build
# 4320에서 개발 서버, 또는 4321에서 빌드 서버를 실행한 뒤
python scripts/tablet-smoke.py
python scripts/tablet-interactions.py
```

빌드 검사에서는 `QA_URL=http://127.0.0.1:4321`을 사용한다. 화면 캡처와 `layout-results.json`은 `docs/reviews/screenshots/tablet-v3/`에 생성된다. 임시 파일·브라우저 프로필·중복 제공 자료·생성된 검사 캡처는 Git에서 제외한다. 실행 에셋, 재작업용 PNG, 로컬 Phaser와 라이선스는 커밋한다.

연결한 GitHub 저장소는 확인 시 커밋이 없는 빈 저장소였다. 이번 프로젝트를 `main`의 첫 커밋으로 기록한다. 사이트 호스팅 배포는 수행하지 않는다.
