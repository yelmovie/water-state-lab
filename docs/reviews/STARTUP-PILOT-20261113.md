# 방울이의 물길 탐험 — 첫 화면과 실험 진입 점검

2026-11-13 · 6번 · 로컬 수정 및 검증. 운영 배포 없음.

타이틀은 엔진, 글꼴, 첫 그림의 완료를 기다리지 않는다. 지도와 캔버스를 쓰는 실험에 들어가면 엔진과 장면 모듈을 요청한다. 화면을 떠난 뒤 완료된 요청은 이전 장면을 다시 그리지 않는다. Phaser를 못 받으면 기존 지도와 실험 도구로 계속할 수 있고, 학생이 원할 때 다시 시도한다. 앱 진입 모듈이 막히면 첫 화면에서 다시 열 수 있다. 오프라인 준비는 기존의 시차·순차 저장을 유지하며, Phaser는 최초 장면 진입 이후에 저장한다.

| 조건 | 첫 콘텐츠 표시 전 → 후 | 시작 버튼 전 → 후 | 인트로 종료 → 지도 버튼 전 → 후 | 샘터 이동 → 첫 실험 버튼 전 → 후 | 샘터 이동 → Phaser 무대 전 → 후 |
|---|---:|---:|---:|---:|---:|
| 일반 로컬 | 68 → 32ms | 87 → 37ms | 10 → 8ms | 14 → 12ms | 31 → 33ms |
| 10Mbps·40ms·CPU 4배 감속 | 808 → 748ms | 3,232 → 1,429ms | 32 → 36ms | 37 → 42ms | 4,408 → 6,969ms |

Chrome 1280×800, 각 조건과 빌드 5회 중앙값. 같은 로컬 서버에서 이전 빌드와 수정 빌드를 교대로 실행. 첫 방문마다 새 브라우저 컨텍스트, HTTP 캐시와 서비스워커 비활성화, 이동 애니메이션 감속 설정. 지도 구간은 인트로 건너뛰기 클릭, 실험 구간은 지도에서 샘터 버튼 클릭부터 잰다. 버튼 준비는 실제 클릭 위치에 다른 요소가 없는 시점이다. 첫 버튼 전에 내려받은 Phaser 1,196,590바이트가 0으로 줄었다. 제한망에서는 엔진을 지도 진입부터 받으므로 그림 무대가 늦게 완성되지만 그 전에 조작할 수 있다. 수치는 운영 서버나 학교 실기기 성능이 아니다.

- Phaser 요청 차단 → 인트로 건너뛰기 → 지도 → 샘터에서 길쭉한 그릇과 넓은 그릇에 각각 100mL를 부었다. 다음 관찰이 열렸고, 차단 해제 후 같은 화면에서 재시도해도 두 기록이 남았다. 앱 진입 파일 요청을 막았을 때 ‘다시 열기’로 돌아왔다.
- 서비스워커 설치 후 타이틀에서는 Phaser 요청과 저장이 없었다. 온라인에서 지도를 한 번 열어 Phaser를 저장한 뒤 연결을 끊고 새로고침해도 지도와 그림 무대가 열렸다.
- ‘추운 밤을 지켜봐’는 물이 오르내리는 동안 기존 통 그림과 수도꼭지를 유지하고, 물높이와 수치만 갱신한다. Chrome에서 1280×800 마우스, 820×650 및 430×800 터치로 길게 담고 키보드로 빼면서 경고 표시를 넘겼다. 기존에는 통 그림 높이가 14.5–18.4px 변했지만 수정 후에는 세 화면 모두 0px였다. SVG가 교체되지 않았고, 다시 열어도 물의 양이 유지됐다. 실제 iPad Safari에서의 재현은 확인하지 않았다.
- 이슬정원의 ‘관찰 마치기’는 이슬정원 응결 영상으로 이어진다. ‘컵에서 찾은 원리로 물을 모아!’는 물길 공방의 ‘더 살펴보기’에서 열리고, 장치 시험을 마친 뒤 ‘이 장치로 출발’을 눌러도 이 설명을 거쳐 온실로 이어진다. 같은 브라우저 세션에서 두 장소를 이어 확인했다.

소스 구문 검사, 단위 테스트 305개와 전체 실험 브라우저 흐름 검사 39개를 통과했다.
