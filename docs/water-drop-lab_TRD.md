# 물방울 연구실 — TRD v3 / MVP

## 1. 기술 결정

MVP는 **표준 ES 모듈 JavaScript + DOM/SVG + Canvas 2D**로 작성한다. 기존 제안의 Phaser/Three.js는 설치하지 않았다. 현재 규모는 표준 브라우저 API로 충분하며, 3D를 배제한 최신 화면 규칙과 외부 의존성 없는 실행을 우선한다. 엔진 도입은 실제 성능·콘텐츠 확장 요구가 생길 때 판단한다.

- Node.js 20+: 개발 HTTP 서버·빌드·테스트에만 사용
- 런타임: 현대 Chrome/Edge/Safari의 ES 모듈, Pointer Events, localStorage
- 외부 CDN/분석/계정/API 호출 없음
- `npm start`, `npm run check`, `npm test`, `npm run build`
- 기본 개발 주소 `http://127.0.0.1:4316`

## 2. 모듈 경계

| 모듈 | 책임 |
|---|---|
| app.js | 라우팅, 공통 헤더/설정/노트, 미션 보상, 결과/인증서 |
| domain.js | 미션/화면 데이터, 얼기·증발·장치 모형, 해금과 완료 순수 함수 |
| state.js | 초기 상태, 저장 버전, 복원 검증, 초기화 |
| experiments.js | 1~8장 렌더링·행동 처리·Pointer/Range 이벤트 |
| workshop.js | 부품 선택·이동·시험, 확정 설계, 최종 연결·레버 |
| map.js | 640×400 픽셀 Canvas 지도. 건물·수로 색으로 복구 표시 |
| ui.js | 버튼, 아이콘, 가상 비커/캔, 안내, 모달 |
| style.css | 색·간격·터치·반응형·인쇄 토큰/스타일 |

화면 렌더는 상태에서 HTML을 생성하고 현재 화면에 필요한 입력 이벤트만 바인딩한다. 상위 클릭 위임은 한 번만 설치한다. 화면 이동 시 엔딩 타이머를 정리한다. 드래그 중에는 해당 SVG transform만 갱신하고 pointerup 시 저장·재렌더한다.

## 3. 라우팅과 해금

라우트는 home / map / 1~10 / ending. 브라우저 경로는 동일하여 새로고침 404를 만들지 않는다. current route와 lastScreen을 저장한다. 모바일 뒤로가기의 별도 히스토리 관리 대신 화면에 명시한 지도·메인 버튼을 사용한다.

`canEnter(screen,state)`가 앞 미션 완료 여부와 짝수 화면의 선행 홀수 화면 완료를 검사한다. ending은 restored=true에서만 허용한다. 미션 완료 시 실제 기록을 evidence에 저장하고 completed에 미션 ID를 한 번만 넣는다.

## 4. 상태

```text
schemaVersion: 1
route / lastScreen
completed: mission IDs
pages: completed screen IDs
evidence: 1~5 actual research records
restored: final lever completed
settings.reduced
lab.observe / classify / freeze / pipe / draw / compare
lab.condensation / evidence / workshop / final
```

키 `water-drop-lab:v1`. 원본 객체는 JSON 직렬화 가능한 값만 담는다. 복원 시 타입, 필수 부품과 좌표, 배열 구조, 화면 해금을 검증한다. 읽기·쓰기·localStorage getter 오류를 잡는다. 알 수 없는 버전/깨진 기록은 기본 상태로 복구한다. 인증서 이름은 상태에 넣지 않는다.

## 5. 가상 실험

### 얼기 / 배관

얼기 공간 비율 1.09는 질적 비교를 시각화하는 모형 상수다. 가상 물높이 60→65.4, 무게 100.0 g 유지, 녹으면 원래 높이. 배관 fill×1.09가 100을 넘으면 위험 높음, 95 초과 보통, 나머지 낮음. 실제 배관 설계 판단에 사용할 수 없다.

### 물그림

500×310 기준 점 배열. A와 B에 같은 점 배열을 그리고 굵기와 유지시간만 다르게 한다. 모형 불투명도 `max(0, 1-time/duration)`, A duration=60, B=110. 타임라인을 되돌리면 같은 기록이 복원된다. 스트로크당 점 수/총 스트로크 수에 상한을 둔다.

### 증발 / 끓음

가상 시간에 따라 수위 감소. 가열 세기 70 이상과 시간 진행 후 내부 기포 표시. 온도계나 실제 시간으로 표현하지 않는다. 가열 세기를 바꾸면 현재 시간은 다시 시작한다. 관찰 근거는 이미 수행한 기록으로 유지한다.

### 응결

닦기·밀봉·영점·처음 측정 전에는 시간 진행 불가. 물방울 수가 시간에 따라 늘고 나중 측정 시 250.0→252.0 g의 가상 기록. 용기와 겉면 물방울을 포함한 측정이라는 조건을 표시한다.

### 물 수집 장치

720×480 2D 작업대. 부품 위치 x/y와 경사값을 저장한다. SVG screenCTM 역변환으로 터치 좌표를 작업대 좌표로 바꾼다. 드래그는 10단위 스냅, 방향 버튼은 20단위 이동.

냉각 → 냉각판 아래 경사판 → 아래쪽 기울기 → 끝 아래 깔때기 → 아래 관 → 아래 물통 순으로 검사한다. 첫 손실 지점을 기록한다. 유효한 경로는 상대 수집 지수 76~85, 끊긴 경로는 수집 0. 실제 유체/열역학 해석은 사용하지 않는다.

각 시험에 `generated/collected/lost/steps/ok/signature` 저장. steps 좌표는 복사하여 이후 이동으로 과거 시험이 바뀌지 않는다. signature는 parts/cold/angle의 JSON이다.

완료 조건: 서로 다른 signature 2개 이상 + 마지막 성공 + 현재 signature와 마지막 시험 일치. evidence[5]에 부품·냉각·경사·결과를 깊은 복사하여 확정한다. 최종 화면은 초안 workshop이 아닌 이 스냅샷만 사용한다. 새 설계를 확정하면 연결·밸브·레버를 초기화한다.

## 6. 접근성과 출력

- 버튼/슬라이더/선택 메뉴는 기본 HTML 요소.
- 주요 드래그에 선택 후 버튼 대체. 자유 그림에는 예시 생성 대체.
- 모달은 native dialog, 포커스/ESC 지원. 상태 피드백은 role=status.
- 한글 keep-all, 여러 화면 폭 대응, reduced-motion 지원.
- 인증서는 print CSS, 이름은 textContent로 출력.
- 오디오·동영상 없음. 음소거 제어가 필요하지 않다.

## 7. 에셋과 배포

사용자 제공 PNG 3개만 public/assets에 복사. 나머지 원본/샘플은 보존하고 dist에 넣지 않는다. 표기는 public/assets/CREDITS.md. 빌드는 src와 실제 assets, index.html을 dist로 복사한다.

도메인 루트 정적 호스팅을 전제로 `/src`, `/assets`를 사용한다. 하위 경로에는 별도 base path 대응 필요. 개발 서버는 127.0.0.1에 바인딩하고 파일 경로를 루트 내부로 제한한다. 외부 공개·Git push·계정 설정은 하지 않는다.

## 8. 검증

Node 내장 test runner로 상태 복원/손상, 단계 해금, 물그림 비교, 장치 경로, 설계 수정, 시험 시점 기록, 확정 설계 분리를 검사한다. 브라우저에서 10장 완주, 오답 피드백, 직접 드로잉, 장치 이동, 새로고침, 결과·인증서를 확인한다.

주력 1280×800과 1024×768, 보조 1920×1080·915×412·375px 폭을 확인한다. 가로 넘침/조작 불가를 수정하고 세로 스크롤은 허용한다. 실기기 성능·학교망·외부 배포는 별도 검증 대상이다.

## 9. 후속 개선

- 정식 실험 기구·캐릭터 아트 교체 시 로직을 보존한다.
- 전자칠판 큰 글씨 모드, 현상 애니메이션의 연속성, 실제 그림 스냅샷, 관찰 비교 리플레이.
- 교사용 해금·학습 리포트 확장은 사용자 요청 후 결정한다.
- 형식 정리/타입 도입, 단계별 모듈 분리는 MVP 피드백 뒤 진행한다.
