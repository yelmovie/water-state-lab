## 2026-09-24 · MVP 완성

**약했던 점.** 첫 구현을 완주하며 결함 8개를 찾았다.

- 성공한 시험 뒤에 설계를 바꿔도 완료됐다.
- 마지막 화면이 수정 중인 공방 설계를 썼다.
- 부품을 옮기면 과거 시험의 위치 기록도 바뀌었다.
- 저장소 접근이 막힌 브라우저에서 처음 실행이 실패했다.
- 손상된 부품 저장 때문에 화면이 멈췄다.
- 예상·실제 수위선과 비커 물높이가 어긋났다.
- 결과를 본 뒤 예상값을 바꿀 수 있었다.
- 캔을 닦기만 해도 '다시 생김' 관찰이 완료됐다.

**바꾼 것.** 현재 배치와 마지막 시험의 일치 요구, 확정 설계를 깊은 복사로 분리, 시험 시 좌표 복사, 저장소 예외 처리, 저장 구조 검증, 같은 SVG 좌표계로 통합, 얼린 뒤 예상 잠금, 닦은 뒤 시간 진행을 완료 조건에 추가.

**확인.** `npm run check`·`npm run build` 통과, 테스트 13개 통과. 실제 브라우저로 메인 → 지도 → 10장 → 코어 복구 → 결과 완주, 콘솔 오류 0. 새로고침 복원·초기화·인증서 표시 확인.

**남은 것.** 전자칠판 글자 크기(내부 점검 7점, FAIL), 터치 실기기·학교망, 원문 교육과정 대조, 제공 이미지의 배포 권리. 내부 21항목 점검 168/198.

## 2026-10-15 · 탐구 여정 2.0

**약했던 점.** MVP는 방울이 벡터 캐릭터 1종, 규칙 기반 물길 등으로 간소화돼 있었다. 장과 장 사이에 무엇을 가져가는지가 화면에서 약했다.

**바꾼 것.**

- 첫 화면을 생성 이미지 연구섬으로 바꾸고, 방울이가 그림 속 길 좌표를 따라 이동한다.
- 사용자 제공 방울이 16개 포즈를 적용했다. 새 지도 1장, 실험 도구 9종, 공방 부품·코어 6종을 생성했다.
- 앞 장 결과를 다음 장 재료로 연결했다(관찰 → 분류, 측정 → 배관 공간 판단, 컵 관찰 → 8장 증거).
- 속도나 반복 클릭이 아니라 관찰·조건 비교·증거 설명·수정한 설계에 보상한다.
- 교사용 전체 해금의 예시 데이터가 학생 완료 기록에 들어가지 않게 했다.
- 검사 중 8번 설명 칸의 닫히지 않은 HTML 태그를 고쳤다.

**확인.** 테스트 27개(1~8장 handler 순서, 저장 손상·구버전 복원, 관리자 격리 포함). 분리된 주소에서 1~10장 수행 후 연구 기록 5/5·엔딩. 1280×800, 1920×1080, 1024×768, 915×412, 375×812 화면 확인. 빌드본 별도 주소에서 저장 복원.

**남은 것.** 학생 이해도·소요 시간, 학교 기기·와이파이, 오프라인, 공개 배포 검증.

## 2026-10-18 · 태블릿 실험 무대 복구

**약했던 점.** 중단됐던 Phaser 실험 무대 작업을 이어 보니 실행을 막는 문제가 있었다.

- 예전 두 열 레이아웃이 남아 실험 무대 폭이 0으로 줄었다.
- 숨김 상태 크기로 Phaser가 계산돼 도구가 매우 작게 보였다.
- 세로 화면에서 실험 패널이 가로로 넘쳤다.
- 캔버스 분류에서 버튼 분류로 바꾸면 이전 카드가 선택된 채 남았다.
- 캔버스에 가려진 돋보기 관찰 버튼을 누를 수 없었다.

**바꾼 것.** 작업 영역을 한 열로 지정, ResizeObserver로 실제 무대 크기를 Phaser에 전달, 패널 최소 폭 0, 분류 성공 뒤 선택 해제, 돋보기 버튼을 도구 패널 대체 조작에 연결.

**확인.** 테스트 42개. 지도와 1~10장 × 6개 화면 크기 66개 통과, 가로 넘침·스크립트 오류·HTTP 오류 0. 코어의 두 고장(냉각 중단·연결 어긋남)을 각각 진단 → 수리 → 재시험 → 엔딩·새로고침 복원. 이 날 프로젝트를 GitHub `main`의 첫 커밋으로 올렸다.

**남은 것.** 실제 학교 태블릿 터치·성능. 1~8장 순서 완주는 브라우저가 아닌 자동 테스트로 확인했다.

## 2026-10-24 · 전체 페이지 고도화

## 2026-10-25 · 스테이지 수정

**약했던 점.**

- 4장: 기본 실험의 95% 한계와 의뢰의 100% 한계가 반대 답처럼 보였다.
