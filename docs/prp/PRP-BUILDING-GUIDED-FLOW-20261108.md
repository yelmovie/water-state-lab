# 큰 실험 화면과 건물별 자동 관찰 흐름

2026-11-08 사용자 요청에 따른 구현 범위. 추가 배포·외부 공유는 포함하지 않는다.

## 목표

- 윈도우 가로 화면에서 실험 그림과 조작 무대를 크게 보여 준다. 긴 안내·중복 단계 표시·큰 시간 막대가 장면을 밀어내지 않게 한다.
- 건물 5곳의 대표 주민은 파랑·뚝딱·보리·송이·느티 5명이다. 관련 두 실험과 현장 관찰은 건물 안에서 이어진다.
- 관찰·물 붓기·얼리기·기다리기·기록·반복 확인은 자동 진행한다. 예측·판단을 묻는 순간에만 큰 선택지를 보여 준다. 직접 실험 조작과 일시 정지는 계속 가능하다.
- 컵 → 얼음틀은 실제 출수구와 칸 위치를 연결하고, 컵의 물이 줄어드는 만큼 여섯 칸이 차례로 찬다. 도중에 멈추거나 새로고침해도 이미 부은 양을 보존한다.

## 현재 구조와 최소 변경

기존 DOM/Phaser 구조와 1–10 내부 경로, 다섯 구역 완료 기록, 관찰 결과를 유지한다. 저장을 삭제하거나 초기화하지 않는다. 대표 주민 조회와 기존 주민 인사 기록 호환을 한 곳에서 처리한다. 새 의존성은 추가하지 않는다.

`freeze-tray.js/css`, `fieldwork-model.js`에서 먼저 큰 실험 무대와 물 붓기를 완성한다. `observation-play.js`, `stage-assist.js`, `app.js`, `inquiry.js`와 공통 레이아웃에서 자동 관찰·질문 경계를 정리한다. `island-residents.js`, 편지·인증서·지도 호출부는 대표 주민 5명으로 맞춘다.

## 저장과 학습 조건

얼음틀의 선택적 `moves.freezeFill`만 0–100의 문자열로 추가한다. 이전의 즉시 `fill` 동작과 옛 기록은 계속 읽는다. 부분 물 붓기로 냉동고 투입이나 발견 도장을 얻지 않는다. 질문의 답을 자동으로 선택하지 않는다. 예측은 틀려도 실제 관찰을 이어서 비교할 수 있다.

## 검증

상태와 진행 로직은 테스트를 먼저 만든다. 대표 얼음틀 화면을 1920×1080, 1536×864, 1366×768, 1024×768, 915×412, 390×844에서 확인한 다음 나머지 장면으로 확장한다. 실제 물줄기 접점·컵 물높이·여섯 칸 진행·중단·재개·버튼·드래그·모션 감소·새로고침을 브라우저에서 확인한다. 전체 자동 관찰은 질문 경계와 답변 후 재개를 검증한다.

`npm run check`, `npm test`, `npm run build`, 화면 겹침·가림·404 검사, 실제 스크린샷을 함께 확인한다. 맥의 Chromium에서 윈도우 대표 화면 크기를 재현하며 실제 Windows 기기 성능은 미실측으로 남긴다.

## 음성 병행 작업

외장 SSD의 독립 실행기로 Qwen3-TTS 한국어 Sohee와 새로 설계한 한국어 남성 샘플을 생성했다. 피치·속도 후처리는 사용하지 않는다. Azure SDK는 별도 외장 폴더에 설치했고 계정 인증이 없어 서비스 생성은 대기 상태다. 모모 도구·API는 사용하지 않는다. 게임의 음성을 대량 교체하기 전에 생성 샘플과 캐릭터 배정을 구분해 검증한다.

## 복구

소스 변경만 되돌리면 기존 흐름으로 돌아간다. `freezeFill`을 모르는 이전 코드는 미완료 상태로 읽는다. 기존 생성 음성·이미지·학생 관찰 기록은 삭제하지 않는다.
