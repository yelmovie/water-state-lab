## 1. 이번에 확정한 화면 규칙

**메인 → 스테이지 지도 → 핵심 실험 10장 → 결과·인증서**

메인과 지도는 핵심 10장에 포함하지 않는다. 심화 설계 v2는 1장을 관찰, 2장을 근거 기록으로 분리하므로 이 구조를 채택한다. 기존 PRD의 ‘1장=메인’ 구조는 폐기한다.

- 스테이지 지도만 위에서 비스듬히 내려다보는 **2.5D 픽셀아트 RPG** 시점이다.
- 메인·1~10장·엔딩은 **2D**로 구현한다. 제공된 배경은 사전 렌더 이미지이며 실험 공간을 3D로 조작하지 않는다.
- 배관은 2D 단면, 장치 공방은 정면 2D 조립 작업대다. Three.js/3D 카메라를 쓰지 않는다.
- 기존 샘플은 색감·분위기 참고용이다. 글자가 들어간 샘플 페이지를 화면 전체에 붙이지 않는다.

## 2. 사건과 역할

학생은 물방울 연구실의 신입 연구원이다. 중앙 Water Core가 멈춰 다섯 구역의 물길이 끊겼다. 방울이는 정답 대신 관찰할 지점을 알려 주며, 학생은 관찰·측정·비교·증거 분석·설계를 통해 연구 기록을 되찾는다.

미션을 완료하면 연구 기록이 생기고 지도에서 해당 구역의 불빛과 물길이 복원된다. 다섯 미션 완료만으로 복구 100%가 되지 않는다. 마지막에 장치 연결·밸브·물길 시험·레버를 직접 조작해야 완료된다.

## 3. 장별 시나리오

| 화면 | 문제와 학생 행동 | 다음 단계로 가져가는 것 |
|---|---|---|
| 메인 | 멈춘 물길과 신입 연구원의 역할을 소개. 시작/이어하기 | 연구 목적 |
| 지도 | 다섯 연구 구역을 선택. 앞 미션 완료 시 다음 구역 해금 | 진행과 복구의 시각적 변화 |
| 01 같은 물, 다른 모습 | 물 붓기, 얼음 이동, 젖은 천 시간 관찰, 차가운 캔 닦기. 네 대상 관찰 | 네 가지 관찰 기록 |
| 02 상태와 근거 | 앞 장 관찰을 보고 상태와 근거를 연결. 천에서 공기로 변한 물은 수증기라는 대상 구분 | 상태 관찰 기록 / 미션 1 완료 |
| 03 얼기 전후 | 빈 저울 영점 → 물 올리기·처음 기록 → 높이 예상 → 얼리기·측정 → 다시 녹이기 | 처음·예상·결과, 무게 유지와 녹기 기록 |
| 04 얼음 배관 | 물의 양을 바꾸어 최소 2개 조건 냉각 시험. 얼음과 남은 공간을 보고 위험 낮은 조건과 근거 선택 | 얼기 전후 측정 데이터 / 미션 2 완료 |
| 05 물그림 | A에 자유 물그림. 같은 모양을 B에 더 많은 물로 재현. 시간을 되돌리거나 보내며 사라지는 순서 관찰 | 한 조건만 바꾼 비교 기록 |
| 06 증발과 끓음 | 가열하지 않은 물과 가열한 물 동시 관찰. 표면·물속·수위를 기록하고 공통점 연결 | 증발·끓음 비교 기록 / 미션 3 완료 |
| 07 컵 밖 물방울 | 닦기·밀봉·빈 저울 영점 → 처음 무게 → 시간 관찰 → 나중 무게·표면 기록 | 처음/나중 응결 증거 |
| 08 증거 분석 | 확보한 증거 2개 이상 선택. 공기 중 수증기 → 차가운 표면 → 액체 물방울 연결. 음료병 사례 적용 | 응결 증거 보고서 / 미션 4 완료 |
| 09 장치 공방 | 냉각판·경사판·깔때기·관·물통 배치. 경사 조절 → 시험 → 손실 위치 확인 → 수정 → 재시험 | 실제 시험한 확정 설계 / 미션 5 완료 |
| 10 코어 재가동 | 다섯 기록 제출 → 확정한 내 장치 출구 연결 → 밸브 열기 → 물길 시험 → 코어 레버 당기기 | 복구 100%, 자신의 기록이 반영된 결과 |
| 결과·인증서 | 코어 점등과 2D 성취 연출, 탐구 스타일·실험 횟수, 이름 선택 입력 후 인쇄/PDF | 개인 연구 인증서 |

## 4. 핵심 상호작용과 완료 조건

- 관찰 없이 다음 단계로 넘어가지 않는다. 예상 자체의 정오로 감점하지 않는다.
- 1장: 물 붓기/시간 조절의 변화 관찰, 얼음 이동, 캔 닦기 모두 수행.
- 2장: 네 사례의 상태와 관찰 근거 모두 기록.
- 3장: 준비·예상·얼기 측정·녹기 확인. 결과를 본 뒤 예상값을 고칠 수 없다.
- 4장: 서로 다른 물의 양 2개 이상 시험. 낮은 위험과 ‘얼음이 커질 여유 공간’ 근거 연결.
- 5장: 그림 생성 후 시간 비교. A의 얇은 물자국이 먼저 사라졌음을 관찰.
- 6장: 표면·내부 기포·수위 근거 3개와 공통점 확보.
- 7장: 준비 완료 전 시간 진행 불가. 처음/나중 기록 확보.
- 8장: 증거 2개, 올바른 인과 순서, 생활 사례 적용.
- 9장: 다른 설계로 2회 이상 시험, 최종 시험 성공, 현재 배치와 마지막 시험의 일치.
- 10장: 다섯 기록과 확정 설계를 사용. 자동 완료 버튼으로 대체하지 않는다.

## 5. 과학 표현

- 수증기는 눈에 보이지 않는 기체 상태의 물이다. 흰 김·구름 캐릭터를 수증기로 그리지 않는다.
- 입자/분자 운동으로 원인을 설명하지 않는다.
- 얼기 전후 같은 양의 물의 무게는 유지되고 차지하는 공간은 커지는 관찰을 중심으로 한다.
- 얼기 모형은 물이 새거나 증발하지 않는 조건이다. 수위·무게는 가상 값임을 표시한다.
- 배관 모형은 실제 수도관 안전 수칙이나 압력 계산이 아니다.
- 응결은 밀봉, 표면 변화, 무게 기록을 함께 사용한다. 무게 변화 하나만으로 모든 원인을 확정하지 않는다.
- 장치 수집량은 0~100 상대 지수다. 실제 물 생산량을 예측하지 않는다.
- 물그림 두 조건은 모양과 환경을 같게 두고 물의 양만 달리한다.

성취기준은 사용자 문서의 [4과10-01] 물의 세 상태, [4과10-02] 얼기·녹기·증발·끓음·응결 관찰, [4과10-03] 물을 얻는 장치 설계와 연결한다. 정식 출시 시 원문 교육과정 대조 검수를 진행한다.

## 6. MVP 범위와 제외

포함: 메인/지도/10장/결과, 5개 기록과 해금, 2D 조립·가상 시험, 자동 저장·이어하기, 연구노트, 움직임 줄이기, 인증서 인쇄.

간소화: 방울이 MVP 벡터 캐릭터 1종, 사진 대신 전후 관찰 기록, 2D 엔딩, 장치의 규칙 기반 물길, 기록에 근거한 간단한 탐구 스타일.

후속: 정식 캐릭터 개별 에셋, 음성/BGM, 20~25초 영화, 보너스 퀘스트, 교사용 일괄 해금, 실제 학교 기기 성능 검증, 오프라인 설치.

## 7. 디자인

원본의 밝은 유리 연구실, 아쿠아·청록·크림·절제된 금색을 사용한다. 실험 물체를 크게 놓고 설명·버튼은 HTML로 렌더링한다. 픽셀 지도와 정면 2D 실험이 명확히 구분되도록 한다. 한글은 어절 단위 줄바꿈, 색과 함께 문구/체크/잠금 표시를 사용한다.

태블릿·데스크톱 가로 우선. 작은 화면은 실험과 조작 패널을 세로로 배치해 가로 넘침을 막는다. 세로 스크롤은 허용한다. 전자칠판 전용 큰 글씨 모드는 후속 범위다.

## 8. 저장·개인정보

로그인과 백엔드 없음. 이 브라우저에 미션 상태·실험 조건·그림·설계·기록을 저장한다. 인증서 이름은 저장/전송하지 않는다. 초기화는 별도 확인을 거친다. 저장 차단 브라우저는 메모리로 실행한다.

## 9. 완료 기준

- 시작부터 10장 레버 및 인증서까지 실제 조작으로 도달.
- 잘못된 근거/미실험 설계는 통과하지 않음.
- 실험 중 새로고침 후 상태 복원.
- 지도만 2.5D, 실험·최종 행동은 2D.
- 확정 설계가 공방의 후속 수정과 분리돼 최종 행동에 재사용.
- 빌드, 도메인 회귀 테스트, 주요 화면 실측 결과 기록.
